# GitLab 用户和权限管理

## 一、用户管理

### 1.1 用户类型

GitLab 有以下几种用户类型：

| 用户类型 | 说明 | 权限 |
|---------|------|------|
| **管理员** | 系统管理员 | 所有权限 |
| **普通用户** | 标准用户 | 根据项目权限 |
| **外部用户** | 外部协作者 | 受限权限 |
| **机器人用户** | 自动化账号 | API 访问 |

### 1.2 创建用户

#### 通过 Web 界面创建

```
1. 以管理员身份登录
2. Admin Area → Users
3. 点击 "New user"
4. 填写用户信息：
   - Name：用户名称
   - Username：登录用户名
   - Email：邮箱地址
   - Access level：访问级别
5. 点击 "Create user"
```

#### 通过命令行创建

```bash
# 进入 GitLab Rails 控制台
sudo gitlab-rails console

# 创建用户
user = User.new(
  username: 'zhangsan',
  email: 'zhangsan@example.com',
  name: '张三',
  password: 'password123',
  password_confirmation: 'password123'
)
user.skip_confirmation!
user.save!

# 设置为管理员
user.admin = true
user.save!

exit
```

### 1.3 用户管理操作

#### 修改用户信息

```bash
# 通过 Web 界面
Admin Area → Users → 选择用户 → Edit

# 通过命令行
sudo gitlab-rails console

user = User.find_by(username: 'zhangsan')
user.email = 'new-email@example.com'
user.save!
```

#### 重置用户密码

```bash
# 方法1：通过 Web 界面
Admin Area → Users → 选择用户 → Edit → Password

# 方法2：通过命令行
sudo gitlab-rails console

user = User.find_by(username: 'zhangsan')
user.password = 'new_password'
user.password_confirmation = 'new_password'
user.save!
```

#### 禁用/启用用户

```bash
# 通过 Web 界面
Admin Area → Users → 选择用户 → Block/Unblock

# 通过命令行
sudo gitlab-rails console

# 禁用用户
user = User.find_by(username: 'zhangsan')
user.block!

# 启用用户
user.activate!
```

#### 删除用户

```bash
# 通过 Web 界面
Admin Area → Users → 选择用户 → Delete user

# 通过命令行
sudo gitlab-rails console

user = User.find_by(username: 'zhangsan')
user.destroy
```

## 二、组（Group）管理

### 2.1 组的概念

组是 GitLab 中用于组织项目和用户的容器。

**组的优势**：
- 统一管理多个项目
- 共享成员和权限
- 继承权限设置
- 便于团队协作

**组的层级**：
```
顶级组
├── 子组1
│   ├── 项目1
│   └── 项目2
└── 子组2
    ├── 项目3
    └── 项目4
```

### 2.2 创建组

#### 通过 Web 界面

```
1. 点击顶部导航栏的 "+"
2. 选择 "New group"
3. 填写组信息：
   - Group name：组名称
   - Group URL：组 URL
   - Visibility Level：可见性级别
   - Description：描述
4. 点击 "Create group"
```

#### 可见性级别

| 级别 | 说明 | 适用场景 |
|------|------|----------|
| **Private** | 私有，只有成员可见 | 内部项目 ⭐ |
| **Internal** | 内部，登录用户可见 | 公司内部 |
| **Public** | 公开，所有人可见 | 开源项目 |

### 2.3 组成员管理

#### 添加成员

```
1. 进入组页面
2. Settings → Members
3. 点击 "Invite member"
4. 选择用户和角色
5. 点击 "Invite"
```

#### 成员角色

| 角色 | 权限 | 说明 |
|------|------|------|
| **Guest** | 只读 | 查看项目 |
| **Reporter** | 报告者 | 创建 Issue |
| **Developer** | 开发者 | 推送代码 ⭐ |
| **Maintainer** | 维护者 | 管理项目 ⭐ |
| **Owner** | 所有者 | 完全控制 |

#### 移除成员

```
Settings → Members → 选择成员 → Remove member
```

## 三、项目（Project）管理

### 3.1 创建项目

#### 通过 Web 界面

```
1. 点击 "New project"
2. 选择创建方式：
   - Create blank project：空白项目
   - Create from template：从模板创建
   - Import project：导入项目
3. 填写项目信息：
   - Project name：项目名称
   - Project URL：项目 URL
   - Visibility Level：可见性
   - Initialize repository：初始化仓库
4. 点击 "Create project"
```

### 3.2 项目设置

#### 基本设置

```
Settings → General

配置项：
- Project name：项目名称
- Project description：项目描述
- Project avatar：项目头像
- Visibility：可见性
- Project features：功能开关
```

#### 功能开关

```
Settings → General → Visibility, project features, permissions

可配置的功能：
- Issues：问题跟踪
- Repository：代码仓库
- Merge Requests：合并请求
- CI/CD：持续集成
- Wiki：文档
- Snippets：代码片段
- Pages：静态网站
```

### 3.3 项目成员管理

#### 添加成员

```
Project → Settings → Members → Invite member
```

#### 权限继承

```
项目权限 = 组权限 + 项目权限

示例：
- 用户在组中是 Developer
- 在项目中是 Maintainer
- 最终权限：Maintainer（取最高权限）
```

## 四、权限详解

### 4.1 权限矩阵

| 操作 | Guest | Reporter | Developer | Maintainer | Owner |
|------|-------|----------|-----------|------------|-------|
| 查看项目 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 下载代码 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 创建 Issue | ✅ | ✅ | ✅ | ✅ | ✅ |
| 评论 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 创建 MR | ❌ | ❌ | ✅ | ✅ | ✅ |
| 推送代码 | ❌ | ❌ | ✅ | ✅ | ✅ |
| 合并 MR | ❌ | ❌ | ❌ | ✅ | ✅ |
| 管理成员 | ❌ | ❌ | ❌ | ✅ | ✅ |
| 删除项目 | ❌ | ❌ | ❌ | ❌ | ✅ |

### 4.2 分支保护

#### 保护分支

```
Settings → Repository → Protected branches

配置：
- Branch：分支名称（如 main, master）
- Allowed to merge：允许合并的角色
- Allowed to push：允许推送的角色
- Allowed to force push：允许强制推送
```

**推荐配置**：
```
main 分支：
- Allowed to merge：Maintainers
- Allowed to push：No one
- Code owner approval：Required
```

#### 保护标签

```
Settings → Repository → Protected tags

配置：
- Tag：标签名称（如 v*）
- Allowed to create：允许创建的角色
```

## 五、SSH 密钥管理

### 5.1 生成 SSH 密钥

```bash
# 生成 SSH 密钥对
ssh-keygen -t rsa -b 4096 -C "your-email@example.com"

# 查看公钥
cat ~/.ssh/id_rsa.pub
```

### 5.2 添加 SSH 密钥

#### 个人 SSH 密钥

```
1. 用户设置 → SSH Keys
2. 粘贴公钥内容
3. 设置标题（如：My Laptop）
4. 点击 "Add key"
```

#### 部署密钥（Deploy Keys）

```
Project → Settings → Repository → Deploy Keys

用途：
- CI/CD 部署
- 自动化脚本
- 只读访问

配置：
1. 添加公钥
2. 设置标题
3. 选择权限（只读/读写）
4. 点击 "Add key"
```

### 5.3 测试 SSH 连接

```bash
# 测试连接
ssh -T git@gitlab.example.com

# 输出示例：
# Welcome to GitLab, @username!
```

## 六、访问令牌（Access Token）

### 6.1 个人访问令牌

#### 创建令牌

```
User Settings → Access Tokens

配置：
- Name：令牌名称
- Expiration date：过期时间
- Scopes：权限范围
  - api：完整 API 访问
  - read_user：读取用户信息
  - read_repository：读取仓库
  - write_repository：写入仓库
  - read_registry：读取容器镜像
  - write_registry：写入容器镜像
```

#### 使用令牌

```bash
# 克隆仓库
git clone https://oauth2:YOUR_TOKEN@gitlab.example.com/group/project.git

# API 调用
curl --header "PRIVATE-TOKEN: YOUR_TOKEN" \
  "https://gitlab.example.com/api/v4/projects"
```

### 6.2 项目访问令牌

```
Project → Settings → Access Tokens

用途：
- CI/CD 流水线
- 自动化脚本
- 第三方集成
```

### 6.3 组访问令牌

```
Group → Settings → Access Tokens

用途：
- 管理组内所有项目
- 批量操作
```

## 七、LDAP 集成

### 7.1 配置 LDAP

```bash
# 编辑配置文件
sudo vim /etc/gitlab/gitlab.rb
```

```ruby
# LDAP 配置
gitlab_rails['ldap_enabled'] = true
gitlab_rails['ldap_servers'] = YAML.load <<-'EOS'
  main:
    label: 'LDAP'
    host: 'ldap.example.com'
    port: 389
    uid: 'sAMAccountName'
    bind_dn: 'CN=gitlab,OU=Users,DC=example,DC=com'
    password: 'password'
    encryption: 'plain'
    verify_certificates: true
    active_directory: true
    allow_username_or_email_login: true
    base: 'DC=example,DC=com'
    user_filter: ''
    attributes:
      username: ['uid', 'userid', 'sAMAccountName']
      email: ['mail', 'email', 'userPrincipalName']
      name: 'cn'
      first_name: 'givenName'
      last_name: 'sn'
EOS
```

```bash
# 应用配置
sudo gitlab-ctl reconfigure

# 测试 LDAP 连接
sudo gitlab-rake gitlab:ldap:check
```

### 7.2 LDAP 用户同步

```bash
# 手动同步
sudo gitlab-rake gitlab:ldap:group_sync

# 定时同步（添加到 crontab）
0 */6 * * * /opt/gitlab/bin/gitlab-rake gitlab:ldap:group_sync
```

## 八、实战案例

### 案例1：团队权限设置

**场景**：公司有前端、后端、测试三个团队

**实施方案**：
```
1. 创建组结构：
   company（顶级组）
   ├── frontend（前端组）
   ├── backend（后端组）
   └── qa（测试组）

2. 设置组权限：
   - frontend：前端开发者为 Developer
   - backend：后端开发者为 Developer
   - qa：测试人员为 Reporter

3. 创建项目：
   - frontend/web-app
   - backend/api-server
   - qa/test-cases

4. 跨组协作：
   - 后端开发者在前端项目中为 Reporter
   - 测试人员在所有项目中为 Reporter
```

### 案例2：外部协作者管理

**场景**：需要外部顾问访问特定项目

**实施方案**：
```
1. 创建外部用户账号
2. 只添加到特定项目
3. 设置为 Guest 或 Reporter
4. 设置访问过期时间
5. 定期审查外部用户权限
```

### 案例3：CI/CD 权限配置

**场景**：配置自动化部署

**实施方案**：
```
1. 创建部署密钥（Deploy Key）
2. 设置为只读权限
3. 在 CI/CD 中使用
4. 或创建项目访问令牌
5. 设置适当的权限范围
```

## 九、最佳实践

### 9.1 权限管理原则

```
1. 最小权限原则
   - 只授予必要的权限
   - 定期审查权限

2. 分层管理
   - 使用组管理团队
   - 项目继承组权限

3. 保护重要分支
   - main/master 分支保护
   - 要求代码审查

4. 使用访问令牌
   - 避免使用密码
   - 设置过期时间
   - 定期轮换

5. 审计日志
   - 定期检查审计日志
   - 监控异常操作
```

### 9.2 安全建议

```
1. 强制双因素认证（2FA）
2. 定期更新密码策略
3. 限制 SSH 密钥使用
4. 监控访问令牌使用
5. 定期清理不活跃用户
6. 使用 LDAP/SAML 集成
7. 启用审计日志
8. 定期备份数据
```

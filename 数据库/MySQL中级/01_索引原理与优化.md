# 索引原理与优化

## 一、索引概述

### 1.1 什么是索引

索引是一种数据结构，用于快速查找数据，类似于书籍的目录。

**作用**：
- 加快数据检索速度
- 提高查询效率
- 减少磁盘 I/O
- 加速排序和分组

**代价**：
- 占用额外存储空间
- 降低写操作性能（INSERT、UPDATE、DELETE）
- 需要维护成本

### 1.2 索引的类型

**按数据结构分类**：
- B+Tree 索引（最常用）
- Hash 索引
- Full-Text 全文索引
- R-Tree 空间索引

**按功能分类**：
- 主键索引（PRIMARY KEY）
- 唯一索引（UNIQUE）
- 普通索引（INDEX）
- 全文索引（FULLTEXT）

**按列数分类**：
- 单列索引
- 联合索引（复合索引）

## 二、B+Tree 索引原理

### 2.1 B+Tree 结构

```
                    [Root Node]
                   /     |     \
                  /      |      \
            [Node]    [Node]    [Node]
            /  |  \    /  |  \   /  |  \
         [Leaf][Leaf][Leaf][Leaf][Leaf][Leaf]
           ↓     ↓     ↓     ↓     ↓     ↓
        [Data][Data][Data][Data][Data][Data]
```

**特点**：
- 所有数据都存储在叶子节点
- 叶子节点之间有指针连接（双向链表）
- 非叶子节点只存储索引键
- 树的高度较低（通常 3-4 层）
- 支持范围查询

### 2.2 B+Tree vs B-Tree

| 特性 | B+Tree | B-Tree |
|------|--------|--------|
| 数据存储 | 只在叶子节点 | 所有节点 |
| 叶子节点连接 | 有双向链表 | 无 |
| 范围查询 | 高效 | 较慢 |
| 磁盘 I/O | 更少 | 更多 |

### 2.3 为什么 MySQL 使用 B+Tree

- 减少磁盘 I/O 次数
- 支持高效的范围查询
- 叶子节点链表支持顺序访问
- 树的高度低，查询稳定

## 三、索引的创建和删除

### 3.1 创建索引

```sql
-- 创建普通索引
CREATE INDEX idx_name ON students(name);

-- 创建唯一索引
CREATE UNIQUE INDEX idx_email ON students(email);

-- 创建联合索引
CREATE INDEX idx_name_age ON students(name, age);

-- 创建全文索引
CREATE FULLTEXT INDEX idx_content ON articles(content);

-- 使用 ALTER TABLE 创建索引
ALTER TABLE students ADD INDEX idx_age (age);
ALTER TABLE students ADD UNIQUE INDEX idx_phone (phone);

-- 创建表时指定索引
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    email VARCHAR(100),
    INDEX idx_name (name),
    UNIQUE INDEX idx_email (email),
    INDEX idx_name_age (name, age)
);
```

### 3.2 查看索引

```sql
-- 查看表的索引
SHOW INDEX FROM students;

-- 查看索引详细信息
SHOW KEYS FROM students;

-- 查看表结构（包含索引）
SHOW CREATE TABLE students;

-- 使用 information_schema
SELECT * FROM information_schema.STATISTICS
WHERE table_schema = 'mydb' AND table_name = 'students';
```

### 3.3 删除索引

```sql
-- 删除索引
DROP INDEX idx_name ON students;

-- 使用 ALTER TABLE 删除索引
ALTER TABLE students DROP INDEX idx_name;

-- 删除主键索引
ALTER TABLE students DROP PRIMARY KEY;
```

## 四、索引类型详解

### 4.1 主键索引（PRIMARY KEY）

```sql
-- 创建主键索引
CREATE TABLE students (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50)
);

-- 添加主键
ALTER TABLE students ADD PRIMARY KEY (id);

-- 特点
-- 1. 唯一且非空
-- 2. 一个表只能有一个主键
-- 3. InnoDB 使用主键作为聚簇索引
```

### 4.2 唯一索引（UNIQUE）

```sql
-- 创建唯一索引
CREATE UNIQUE INDEX idx_email ON students(email);

-- 允许 NULL 值（多个 NULL）
INSERT INTO students (name, email) VALUES ('张三', NULL);
INSERT INTO students (name, email) VALUES ('李四', NULL);  -- 允许

-- 不允许重复值
INSERT INTO students (name, email) VALUES ('王五', 'test@example.com');
INSERT INTO students (name, email) VALUES ('赵六', 'test@example.com');  -- 错误
```

### 4.3 普通索引（INDEX）

```sql
-- 创建普通索引
CREATE INDEX idx_name ON students(name);

-- 允许重复值和 NULL
-- 最常用的索引类型
```

### 4.4 全文索引（FULLTEXT）

```sql
-- 创建全文索引（仅支持 MyISAM 和 InnoDB）
CREATE TABLE articles (
    id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200),
    content TEXT,
    FULLTEXT INDEX idx_content (content)
);

-- 使用全文索引
SELECT * FROM articles
WHERE MATCH(content) AGAINST('MySQL 教程');

-- 布尔模式
SELECT * FROM articles
WHERE MATCH(content) AGAINST('+MySQL -Oracle' IN BOOLEAN MODE);

-- 查询扩展模式
SELECT * FROM articles
WHERE MATCH(content) AGAINST('MySQL' WITH QUERY EXPANSION);
```

### 4.5 前缀索引

```sql
-- 为长字符串创建前缀索引
CREATE INDEX idx_email_prefix ON students(email(10));

-- 优点：节省空间
-- 缺点：无法用于 ORDER BY 和 GROUP BY

-- 选择合适的前缀长度
SELECT 
    COUNT(DISTINCT LEFT(email, 5)) / COUNT(*) AS sel5,
    COUNT(DISTINCT LEFT(email, 10)) / COUNT(*) AS sel10,
    COUNT(DISTINCT LEFT(email, 15)) / COUNT(*) AS sel15
FROM students;
```

## 五、联合索引（复合索引）

### 5.1 创建联合索引

```sql
-- 创建联合索引
CREATE INDEX idx_name_age_gender ON students(name, age, gender);
```

### 5.2 最左前缀原则

联合索引遵循最左前缀原则，索引可以用于以下查询：

```sql
-- ✅ 使用索引（完整匹配）
SELECT * FROM students WHERE name = '张三' AND age = 20 AND gender = '男';

-- ✅ 使用索引（最左前缀）
SELECT * FROM students WHERE name = '张三';
SELECT * FROM students WHERE name = '张三' AND age = 20;

-- ❌ 不使用索引（跳过最左列）
SELECT * FROM students WHERE age = 20;
SELECT * FROM students WHERE gender = '男';
SELECT * FROM students WHERE age = 20 AND gender = '男';

-- ✅ 部分使用索引（只用到 name）
SELECT * FROM students WHERE name = '张三' AND gender = '男';
```

### 5.3 索引列顺序

```sql
-- 区分度高的列放在前面
-- 假设：name 有 1000 个不同值，age 有 50 个不同值，gender 有 2 个不同值

-- ✅ 推荐
CREATE INDEX idx_name_age_gender ON students(name, age, gender);

-- ❌ 不推荐
CREATE INDEX idx_gender_age_name ON students(gender, age, name);
```

### 5.4 联合索引 vs 多个单列索引

```sql
-- 方案1：联合索引（推荐）
CREATE INDEX idx_name_age ON students(name, age);

-- 方案2：多个单列索引（不推荐）
CREATE INDEX idx_name ON students(name);
CREATE INDEX idx_age ON students(age);

-- 联合索引的优势
-- 1. 减少索引数量
-- 2. 减少存储空间
-- 3. 提高查询效率
```

## 六、索引优化策略

### 6.1 选择合适的列创建索引

```sql
-- ✅ 适合创建索引的列
-- 1. WHERE 条件中的列
SELECT * FROM students WHERE name = '张三';

-- 2. JOIN 条件中的列
SELECT * FROM students s JOIN classes c ON s.class_id = c.id;

-- 3. ORDER BY 的列
SELECT * FROM students ORDER BY age;

-- 4. GROUP BY 的列
SELECT class_id, COUNT(*) FROM students GROUP BY class_id;

-- ❌ 不适合创建索引的列
-- 1. 区分度低的列（如性别）
-- 2. 频繁更新的列
-- 3. 很少使用的列
-- 4. 数据量很小的表
```

### 6.2 覆盖索引

覆盖索引是指索引包含了查询所需的所有列，无需回表查询。

```sql
-- 创建联合索引
CREATE INDEX idx_name_age_email ON students(name, age, email);

-- ✅ 覆盖索引（无需回表）
SELECT name, age, email FROM students WHERE name = '张三';

-- ❌ 非覆盖索引（需要回表）
SELECT name, age, email, address FROM students WHERE name = '张三';

-- 查看是否使用覆盖索引
EXPLAIN SELECT name, age, email FROM students WHERE name = '张三';
-- Extra: Using index（表示使用了覆盖索引）
```

### 6.3 索引下推（Index Condition Pushdown）

MySQL 5.6+ 支持索引下推优化。

```sql
-- 创建联合索引
CREATE INDEX idx_name_age ON students(name, age);

-- 查询
SELECT * FROM students WHERE name LIKE '张%' AND age = 20;

-- 没有索引下推：
-- 1. 使用索引找到所有 name LIKE '张%' 的记录
-- 2. 回表获取完整数据
-- 3. 过滤 age = 20

-- 有索引下推：
-- 1. 使用索引找到 name LIKE '张%' 的记录
-- 2. 在索引中直接过滤 age = 20
-- 3. 回表获取符合条件的完整数据

-- 查看是否使用索引下推
EXPLAIN SELECT * FROM students WHERE name LIKE '张%' AND age = 20;
-- Extra: Using index condition（表示使用了索引下推）
```

## 七、索引失效场景

### 7.1 使用函数或表达式

```sql
-- ❌ 索引失效
SELECT * FROM students WHERE YEAR(create_time) = 2024;
SELECT * FROM students WHERE age + 1 = 21;

-- ✅ 索引有效
SELECT * FROM students WHERE create_time >= '2024-01-01' AND create_time < '2025-01-01';
SELECT * FROM students WHERE age = 20;
```

### 7.2 隐式类型转换

```sql
-- 假设 phone 是 VARCHAR 类型

-- ❌ 索引失效（字符串转数字）
SELECT * FROM students WHERE phone = 13800138000;

-- ✅ 索引有效
SELECT * FROM students WHERE phone = '13800138000';
```

### 7.3 LIKE 以通配符开头

```sql
-- ❌ 索引失效
SELECT * FROM students WHERE name LIKE '%三';
SELECT * FROM students WHERE name LIKE '%张%';

-- ✅ 索引有效
SELECT * FROM students WHERE name LIKE '张%';
```

### 7.4 OR 条件

```sql
-- ❌ 索引失效（OR 两边有未索引的列）
SELECT * FROM students WHERE name = '张三' OR address = '北京';

-- ✅ 索引有效（OR 两边都有索引）
SELECT * FROM students WHERE name = '张三' OR email = 'test@example.com';
```

### 7.5 NOT、!=、<>

```sql
-- ❌ 索引失效
SELECT * FROM students WHERE age != 20;
SELECT * FROM students WHERE age <> 20;
SELECT * FROM students WHERE NOT age = 20;

-- ✅ 索引有效（改写查询）
SELECT * FROM students WHERE age < 20 OR age > 20;
```

### 7.6 IS NULL 和 IS NOT NULL

```sql
-- 可能失效（取决于 NULL 值的比例）
SELECT * FROM students WHERE email IS NULL;
SELECT * FROM students WHERE email IS NOT NULL;

-- 如果 NULL 值很多，IS NOT NULL 可能不走索引
-- 如果 NULL 值很少，IS NULL 可能走索引
```

## 八、EXPLAIN 分析索引

### 8.1 EXPLAIN 基础

```sql
EXPLAIN SELECT * FROM students WHERE name = '张三';
```

### 8.2 EXPLAIN 输出字段

| 字段 | 说明 |
|------|------|
| id | 查询序号 |
| select_type | 查询类型 |
| table | 表名 |
| type | 访问类型 |
| possible_keys | 可能使用的索引 |
| key | 实际使用的索引 |
| key_len | 索引长度 |
| ref | 索引引用 |
| rows | 扫描行数 |
| Extra | 额外信息 |

### 8.3 type 访问类型（性能从好到差）

```sql
-- system：表只有一行
-- const：主键或唯一索引查询
EXPLAIN SELECT * FROM students WHERE id = 1;

-- eq_ref：唯一索引扫描
EXPLAIN SELECT * FROM students s JOIN classes c ON s.class_id = c.id;

-- ref：非唯一索引扫描
EXPLAIN SELECT * FROM students WHERE name = '张三';

-- range：范围扫描
EXPLAIN SELECT * FROM students WHERE age BETWEEN 18 AND 25;

-- index：索引全扫描
EXPLAIN SELECT id FROM students;

-- ALL：全表扫描（最差）
EXPLAIN SELECT * FROM students WHERE address = '北京';
```

### 8.4 Extra 额外信息

```sql
-- Using index：使用覆盖索引
EXPLAIN SELECT name FROM students WHERE name = '张三';

-- Using where：使用 WHERE 过滤
EXPLAIN SELECT * FROM students WHERE age > 20;

-- Using index condition：使用索引下推
EXPLAIN SELECT * FROM students WHERE name LIKE '张%' AND age = 20;

-- Using filesort：需要额外排序（性能差）
EXPLAIN SELECT * FROM students ORDER BY address;

-- Using temporary：使用临时表（性能差）
EXPLAIN SELECT DISTINCT address FROM students;
```

## 九、索引优化实战

### 9.1 慢查询优化案例

```sql
-- 原始查询（慢）
SELECT * FROM orders 
WHERE user_id = 1001 
  AND status = 'paid' 
  AND create_time >= '2024-01-01'
ORDER BY create_time DESC
LIMIT 10;

-- 分析
EXPLAIN SELECT * FROM orders 
WHERE user_id = 1001 
  AND status = 'paid' 
  AND create_time >= '2024-01-01'
ORDER BY create_time DESC
LIMIT 10;

-- 优化：创建联合索引
CREATE INDEX idx_user_status_time ON orders(user_id, status, create_time);

-- 优化后查询
-- type: ref
-- key: idx_user_status_time
-- Extra: Using index condition
```

### 9.2 分页查询优化

```sql
-- ❌ 深分页性能差
SELECT * FROM students LIMIT 100000, 10;

-- ✅ 使用主键优化
SELECT * FROM students WHERE id > 100000 LIMIT 10;

-- ✅ 使用子查询优化
SELECT * FROM students 
WHERE id >= (SELECT id FROM students LIMIT 100000, 1)
LIMIT 10;

-- ✅ 使用延迟关联
SELECT s.* FROM students s
JOIN (SELECT id FROM students LIMIT 100000, 10) t ON s.id = t.id;
```

## 十、索引监控和维护

### 10.1 查看索引使用情况

```sql
-- 查看索引统计信息
SELECT * FROM sys.schema_unused_indexes;

-- 查看索引大小
SELECT 
    table_name,
    index_name,
    ROUND(stat_value * @@innodb_page_size / 1024 / 1024, 2) AS size_mb
FROM mysql.innodb_index_stats
WHERE database_name = 'mydb'
ORDER BY stat_value DESC;
```

### 10.2 重建索引

```sql
-- 删除并重建索引
DROP INDEX idx_name ON students;
CREATE INDEX idx_name ON students(name);

-- 使用 ALTER TABLE 重建
ALTER TABLE students DROP INDEX idx_name, ADD INDEX idx_name (name);

-- 优化表（重建索引和整理碎片）
OPTIMIZE TABLE students;
```

### 10.3 索引碎片整理

```sql
-- 查看表碎片
SELECT 
    table_name,
    data_free / 1024 / 1024 AS fragmentation_mb
FROM information_schema.tables
WHERE table_schema = 'mydb';

-- 整理碎片
OPTIMIZE TABLE students;
-- 或
ALTER TABLE students ENGINE=InnoDB;
```

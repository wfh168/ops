## 1. 事务基础

### 1.1 什么是事务

事务（Transaction）是数据库操作的最小工作单元，是一组不可分割的操作集合。

**经典案例：银行转账**
```sql
-- 张三给李四转账 1000 元
START TRANSACTION;

-- 1. 张三账户减少 1000
UPDATE accounts SET balance = balance - 1000 WHERE user = '张三';

-- 2. 李四账户增加 1000
UPDATE accounts SET balance = balance + 1000 WHERE user = '李四';

COMMIT;  -- 提交事务
```

### 1.2 ACID 特性

| 特性 | 英文 | 说明 |
|------|------|------|
| 原子性 | Atomicity | 事务中的所有操作要么全部成功，要么全部失败 |
| 一致性 | Consistency | 事务前后数据的完整性必须保持一致 |
| 隔离性 | Isolation | 多个事务并发执行时，相互之间不受影响 |
| 持久性 | Durability | 事务一旦提交，对数据的改变是永久的 |

## 2. 事务操作

### 2.1 基本语法

```sql
-- 开启事务
START TRANSACTION;
-- 或
BEGIN;

-- 执行 SQL 操作
UPDATE ...
INSERT ...
DELETE ...

-- 提交事务
COMMIT;

-- 回滚事务
ROLLBACK;
```

### 2.2 自动提交

```sql
-- 查看自动提交状态
SHOW VARIABLES LIKE 'autocommit';

-- 关闭自动提交
SET autocommit = 0;

-- 开启自动提交
SET autocommit = 1;
```

### 2.3 保存点（Savepoint）

```sql
START TRANSACTION;

INSERT INTO users (username) VALUES ('user1');

-- 设置保存点
SAVEPOINT sp1;

INSERT INTO users (username) VALUES ('user2');

-- 设置另一个保存点
SAVEPOINT sp2;

INSERT INTO users (username) VALUES ('user3');

-- 回滚到 sp2
ROLLBACK TO sp2;  -- user3 被回滚

-- 回滚到 sp1
ROLLBACK TO sp1;  -- user2 和 user3 被回滚

COMMIT;  -- 只有 user1 被提交
```

### 2.4 实战示例

**示例1：订单处理**

```sql
-- 创建测试表
CREATE TABLE products_tx (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    stock INT,
    price DECIMAL(10,2)
);

CREATE TABLE orders_tx (
    id INT PRIMARY KEY AUTO_INCREMENT,
    product_id INT,
    quantity INT,
    total_amount DECIMAL(10,2),
    status VARCHAR(20)
);

-- 插入测试数据
INSERT INTO products_tx (name, stock, price) 
VALUES ('iPhone 15', 100, 5999.00);

-- 下单事务
START TRANSACTION;

-- 1. 检查库存
SELECT stock INTO @current_stock 
FROM products_tx WHERE id = 1;

-- 2. 如果库存充足，创建订单
IF @current_stock >= 2 THEN
    INSERT INTO orders_tx (product_id, quantity, total_amount, status)
    VALUES (1, 2, 5999.00 * 2, 'pending');
    
    -- 3. 扣减库存
    UPDATE products_tx SET stock = stock - 2 WHERE id = 1;
    
    COMMIT;
ELSE
    ROLLBACK;
END IF;
```

**示例2：转账事务**

```sql
-- 创建账户表
CREATE TABLE bank_accounts (
    id INT PRIMARY KEY AUTO_INCREMENT,
    account_no VARCHAR(20) UNIQUE,
    username VARCHAR(50),
    balance DECIMAL(12,2) DEFAULT 0,
    CHECK (balance >= 0)
);

-- 插入测试数据
INSERT INTO bank_accounts (account_no, username, balance)
VALUES 
    ('6222001234567890', '张三', 10000.00),
    ('6222009876543210', '李四', 5000.00);

-- 转账存储过程
DELIMITER $$
CREATE PROCEDURE transfer_money(
    IN from_account VARCHAR(20),
    IN to_account VARCHAR(20),
    IN amount DECIMAL(12,2)
)
BEGIN
    DECLARE from_balance DECIMAL(12,2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SELECT '转账失败，事务已回滚' AS message;
    END;
    
    START TRANSACTION;
    
    -- 检查余额
    SELECT balance INTO from_balance
    FROM bank_accounts
    WHERE account_no = from_account
    FOR UPDATE;  -- 加锁
    
    IF from_balance < amount THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '余额不足';
    END IF;
    
    -- 扣款
    UPDATE bank_accounts
    SET balance = balance - amount
    WHERE account_no = from_account;
    
    -- 入账
    UPDATE bank_accounts
    SET balance = balance + amount
    WHERE account_no = to_account;
    
    COMMIT;
    SELECT '转账成功' AS message;
END$$
DELIMITER ;

-- 测试转账
CALL transfer_money('6222001234567890', '6222009876543210', 1000.00);

-- 查看结果
SELECT * FROM bank_accounts;
```

## 3. 事务隔离级别

### 3.1 并发问题

| 问题 | 说明 | 示例 |
|------|------|------|
| 脏读 | 读到其他事务未提交的数据 | 事务A读到事务B未提交的修改 |
| 不可重复读 | 同一事务中多次读取结果不一致 | 事务A两次读取，期间事务B修改并提交 |
| 幻读 | 同一事务中多次查询记录数不一致 | 事务A两次查询，期间事务B插入新记录 |

### 3.2 四种隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|---------|------|-----------|------|------|
| READ UNCOMMITTED | ✅ 可能 | ✅ 可能 | ✅ 可能 | 最低级别，性能最好 |
| READ COMMITTED | ❌ 不可能 | ✅ 可能 | ✅ 可能 | Oracle 默认 |
| REPEATABLE READ | ❌ 不可能 | ❌ 不可能 | ✅ 可能 | MySQL 默认 |
| SERIALIZABLE | ❌ 不可能 | ❌ 不可能 | ❌ 不可能 | 最高级别，性能最差 |

### 3.3 查看和设置隔离级别

```sql
-- 查看全局隔离级别
SELECT @@global.transaction_isolation;

-- 查看会话隔离级别
SELECT @@session.transaction_isolation;

-- 设置会话隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE;

-- 设置全局隔离级别
SET GLOBAL TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

### 3.4 隔离级别演示

**演示1：脏读（READ UNCOMMITTED）**

```sql
-- 会话1
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
UPDATE bank_accounts SET balance = 20000 WHERE id = 1;
-- 不提交

-- 会话2
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
SELECT balance FROM bank_accounts WHERE id = 1;  -- 读到 20000（脏读）

-- 会话1
ROLLBACK;  -- 回滚

-- 会话2 读到的数据无效了
```

**演示2：不可重复读（READ COMMITTED）**

```sql
-- 会话1
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;
SELECT balance FROM bank_accounts WHERE id = 1;  -- 读到 10000

-- 会话2
START TRANSACTION;
UPDATE bank_accounts SET balance = 15000 WHERE id = 1;
COMMIT;

-- 会话1
SELECT balance FROM bank_accounts WHERE id = 1;  -- 读到 15000（不可重复读）
```

**演示3：幻读（REPEATABLE READ）**

```sql
-- 会话1
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
SELECT COUNT(*) FROM bank_accounts WHERE balance > 5000;  -- 假设结果是 2

-- 会话2
START TRANSACTION;
INSERT INTO bank_accounts (account_no, username, balance)
VALUES ('6222001111111111', '王五', 8000.00);
COMMIT;

-- 会话1
SELECT COUNT(*) FROM bank_accounts WHERE balance > 5000;  
-- MySQL InnoDB 下仍然是 2（通过 MVCC 和 Next-Key Lock 避免了幻读）
```

## 4. 锁机制

### 4.1 锁的分类

**按锁的粒度分类**：
- 表级锁：锁定整张表
- 行级锁：锁定特定行
- 页级锁：锁定数据页

**按锁的类型分类**：
- 共享锁（S锁）：读锁，多个事务可以同时持有
- 排他锁（X锁）：写锁，只有一个事务可以持有

**按锁的模式分类**：
- 乐观锁：假设不会冲突，提交时检查
- 悲观锁：假设会冲突，操作前先加锁

### 4.2 InnoDB 锁类型

```sql
-- 1. 记录锁（Record Lock）
-- 锁定单个行记录
SELECT * FROM users WHERE id = 1 FOR UPDATE;

-- 2. 间隙锁（Gap Lock）
-- 锁定索引记录之间的间隙
SELECT * FROM users WHERE id BETWEEN 5 AND 10 FOR UPDATE;

-- 3. Next-Key Lock
-- 记录锁 + 间隙锁
-- 锁定记录本身和记录前的间隙

-- 4. 插入意向锁（Insert Intention Lock）
-- 插入操作时使用的特殊间隙锁
```

### 4.3 显式加锁

```sql
-- 共享锁（读锁）
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;
-- 或 MySQL 8.0+
SELECT * FROM users WHERE id = 1 FOR SHARE;

-- 排他锁（写锁）
SELECT * FROM users WHERE id = 1 FOR UPDATE;

-- 示例：库存扣减
START TRANSACTION;

-- 加排他锁，防止其他事务修改
SELECT stock INTO @current_stock
FROM products_tx WHERE id = 1
FOR UPDATE;

IF @current_stock >= 10 THEN
    UPDATE products_tx SET stock = stock - 10 WHERE id = 1;
    COMMIT;
ELSE
    ROLLBACK;
END IF;
```

### 4.4 查看锁信息

```sql
-- 查看当前锁
SELECT * FROM performance_schema.data_locks;

-- 查看锁等待
SELECT * FROM performance_schema.data_lock_waits;

-- 查看事务
SELECT * FROM information_schema.INNODB_TRX;

-- 查看锁等待（旧版本）
SHOW ENGINE INNODB STATUS;
```

## 5. 死锁

### 5.1 什么是死锁

死锁是指两个或多个事务相互等待对方释放锁，导致所有事务都无法继续执行。

**经典死锁场景**：

```sql
-- 事务1
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;  -- 锁定 id=1
-- 等待锁定 id=2
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- 事务2（同时执行）
START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 2;  -- 锁定 id=2
-- 等待锁定 id=1
UPDATE accounts SET balance = balance + 100 WHERE id = 1;

-- 结果：死锁！
```

### 5.2 死锁检测

```sql
-- 查看死锁日志
SHOW ENGINE INNODB STATUS;

-- 查看最近一次死锁
SELECT * FROM information_schema.INNODB_METRICS
WHERE NAME = 'lock_deadlocks';

-- 开启死锁日志
SET GLOBAL innodb_print_all_deadlocks = ON;
```

### 5.3 避免死锁

**策略1：按相同顺序访问资源**

```sql
-- ❌ 错误：不同顺序
-- 事务1：先锁 A，再锁 B
-- 事务2：先锁 B，再锁 A

-- ✅ 正确：相同顺序
-- 事务1：先锁 A，再锁 B
-- 事务2：先锁 A，再锁 B
```

**策略2：缩短事务时间**

```sql
-- ❌ 不好
START TRANSACTION;
SELECT * FROM products WHERE id = 1 FOR UPDATE;
-- 执行复杂业务逻辑（耗时长）
-- 调用外部 API
-- 复杂计算
UPDATE products SET stock = stock - 1 WHERE id = 1;
COMMIT;

-- ✅ 好
-- 先完成业务逻辑
-- 计算结果

-- 快速执行事务
START TRANSACTION;
UPDATE products SET stock = stock - 1 WHERE id = 1;
COMMIT;
```

**策略3：降低隔离级别**

```sql
-- 从 SERIALIZABLE 降低到 REPEATABLE READ
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

**策略4：使用索引**

```sql
-- ❌ 没有索引，锁定更多行
UPDATE products SET stock = stock - 1 WHERE name = 'iPhone';

-- ✅ 有索引，只锁定匹配的行
-- 先创建索引
CREATE INDEX idx_name ON products(name);
UPDATE products SET stock = stock - 1 WHERE name = 'iPhone';
```

### 5.4 死锁处理

```sql
-- MySQL 会自动检测死锁并回滚其中一个事务
-- 应用程序应该捕获死锁异常并重试

DELIMITER $$
CREATE PROCEDURE safe_transfer(
    IN from_id INT,
    IN to_id INT,
    IN amount DECIMAL(10,2)
)
BEGIN
    DECLARE retry_count INT DEFAULT 0;
    DECLARE max_retries INT DEFAULT 3;
    DECLARE done INT DEFAULT 0;
    
    WHILE retry_count < max_retries AND done = 0 DO
        BEGIN
            DECLARE EXIT HANDLER FOR 1213  -- 死锁错误码
            BEGIN
                SET retry_count = retry_count + 1;
                IF retry_count >= max_retries THEN
                    SIGNAL SQLSTATE '45000'
                    SET MESSAGE_TEXT = '操作失败：多次重试后仍然死锁';
                END IF;
            END;
            
            START TRANSACTION;
            
            -- 按 ID 顺序加锁，避免死锁
            IF from_id < to_id THEN
                UPDATE accounts SET balance = balance - amount 
                WHERE id = from_id;
                UPDATE accounts SET balance = balance + amount 
                WHERE id = to_id;
            ELSE
                UPDATE accounts SET balance = balance + amount 
                WHERE id = to_id;
                UPDATE accounts SET balance = balance - amount 
                WHERE id = from_id;
            END IF;
            
            COMMIT;
            SET done = 1;
        END;
    END WHILE;
END$$
DELIMITER ;
```

## 6. MVCC 多版本并发控制

### 6.1 什么是 MVCC

MVCC（Multi-Version Concurrency Control）是一种并发控制机制，通过保存数据的多个版本来实现并发控制。

**核心思想**：
- 读不加锁，写不阻塞读
- 通过版本链实现一致性读
- 提高并发性能

### 6.2 实现原理

**隐藏字段**：
```
DB_TRX_ID：事务 ID
DB_ROLL_PTR：回滚指针
DB_ROW_ID：隐藏主键
```

**Undo Log**：
- 记录数据的历史版本
- 用于事务回滚
- 用于 MVCC 读取历史版本

**Read View**：
- 事务开始时创建的快照
- 决定哪些版本对当前事务可见

### 6.3 快照读 vs 当前读

```sql
-- 快照读（使用 MVCC）
SELECT * FROM users WHERE id = 1;

-- 当前读（加锁）
SELECT * FROM users WHERE id = 1 FOR UPDATE;
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;
UPDATE users SET name = 'new' WHERE id = 1;
DELETE FROM users WHERE id = 1;
```

## 7. 实战案例

### 案例1：秒杀系统

```sql
-- 创建秒杀商品表
CREATE TABLE seckill_products (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    stock INT,
    version INT DEFAULT 0,  -- 乐观锁版本号
    start_time DATETIME,
    end_time DATETIME
);

-- 插入测试数据
INSERT INTO seckill_products (name, stock, start_time, end_time)
VALUES ('iPhone 15 秒杀', 100, NOW(), DATE_ADD(NOW(), INTERVAL 1 HOUR));

-- 方案1：悲观锁
DELIMITER $$
CREATE PROCEDURE seckill_pessimistic(
    IN product_id INT,
    IN user_id INT
)
BEGIN
    DECLARE current_stock INT;
    
    START TRANSACTION;
    
    -- 加排他锁
    SELECT stock INTO current_stock
    FROM seckill_products
    WHERE id = product_id
    FOR UPDATE;
    
    IF current_stock > 0 THEN
        -- 扣减库存
        UPDATE seckill_products
        SET stock = stock - 1
        WHERE id = product_id;
        
        -- 创建订单
        INSERT INTO seckill_orders (product_id, user_id)
        VALUES (product_id, user_id);
        
        COMMIT;
        SELECT '秒杀成功' AS message;
    ELSE
        ROLLBACK;
        SELECT '库存不足' AS message;
    END IF;
END$$
DELIMITER ;

-- 方案2：乐观锁
DELIMITER $$
CREATE PROCEDURE seckill_optimistic(
    IN product_id INT,
    IN user_id INT
)
BEGIN
    DECLARE current_version INT;
    DECLARE affected_rows INT;
    
    -- 读取当前版本号
    SELECT version INTO current_version
    FROM seckill_products
    WHERE id = product_id AND stock > 0;
    
    -- 使用版本号更新
    UPDATE seckill_products
    SET stock = stock - 1,
        version = version + 1
    WHERE id = product_id
      AND version = current_version
      AND stock > 0;
    
    SET affected_rows = ROW_COUNT();
    
    IF affected_rows > 0 THEN
        INSERT INTO seckill_orders (product_id, user_id)
        VALUES (product_id, user_id);
        SELECT '秒杀成功' AS message;
    ELSE
        SELECT '秒杀失败' AS message;
    END IF;
END$$
DELIMITER ;
```

### 案例2：分布式锁

```sql
-- 创建锁表
CREATE TABLE distributed_locks (
    lock_name VARCHAR(100) PRIMARY KEY,
    lock_holder VARCHAR(100),
    lock_time DATETIME,
    expire_time DATETIME
);

-- 获取锁
DELIMITER $$
CREATE FUNCTION acquire_lock(
    lock_key VARCHAR(100),
    holder VARCHAR(100),
    timeout_seconds INT
) RETURNS BOOLEAN
BEGIN
    DECLARE lock_acquired BOOLEAN DEFAULT FALSE;
    DECLARE current_time DATETIME DEFAULT NOW();
    DECLARE expire_time DATETIME DEFAULT DATE_ADD(NOW(), INTERVAL timeout_seconds SECOND);
    
    -- 尝试插入锁记录
    INSERT INTO distributed_locks (lock_name, lock_holder, lock_time, expire_time)
    VALUES (lock_key, holder, current_time, expire_time)
    ON DUPLICATE KEY UPDATE
        lock_holder = IF(expire_time < current_time, holder, lock_holder),
        lock_time = IF(expire_time < current_time, current_time, lock_time),
        expire_time = IF(expire_time < current_time, expire_time, expire_time);
    
    -- 检查是否获取到锁
    SELECT (lock_holder = holder) INTO lock_acquired
    FROM distributed_locks
    WHERE lock_name = lock_key;
    
    RETURN lock_acquired;
END$$
DELIMITER ;

-- 释放锁
DELIMITER $$
CREATE PROCEDURE release_lock(
    IN lock_key VARCHAR(100),
    IN holder VARCHAR(100)
)
BEGIN
    DELETE FROM distributed_locks
    WHERE lock_name = lock_key AND lock_holder = holder;
END$$
DELIMITER ;
```

## 8. 性能优化

### 8.1 事务优化

```sql
-- ✅ 好的做法
START TRANSACTION;
-- 只包含必要的 SQL
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;

-- ❌ 不好的做法
START TRANSACTION;
-- 包含大量业务逻辑
SELECT * FROM accounts WHERE id = 1;
-- 复杂计算
-- 调用外部服务
-- 等待用户输入
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
COMMIT;
```

### 8.2 锁优化

```sql
-- 使用索引减少锁范围
CREATE INDEX idx_status ON orders(status);

-- 只锁定需要的行
SELECT * FROM orders 
WHERE status = 'pending' AND id = 1
FOR UPDATE;

-- 避免锁定大量数据
-- ❌ 锁定所有待处理订单
SELECT * FROM orders WHERE status = 'pending' FOR UPDATE;

-- ✅ 分批处理
SELECT * FROM orders 
WHERE status = 'pending' 
LIMIT 100
FOR UPDATE;
```

## 📝 本节总结

### 核心要点

1. **ACID 特性**：原子性、一致性、隔离性、持久性
2. **隔离级别**：READ UNCOMMITTED < READ COMMITTED < REPEATABLE READ < SERIALIZABLE
3. **锁机制**：共享锁、排他锁、行锁、表锁
4. **死锁处理**：按顺序加锁、缩短事务、降低隔离级别
5. **MVCC**：多版本并发控制，提高并发性能

### 最佳实践

```
✅ 保持事务简短
✅ 按相同顺序访问资源
✅ 使用合适的隔离级别
✅ 使用索引减少锁范围
✅ 及时提交或回滚事务
✅ 处理死锁异常并重试
```

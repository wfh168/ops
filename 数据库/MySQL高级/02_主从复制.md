## 1. 主从复制原理

### 1.1 什么是主从复制

主从复制（Replication）是 MySQL 的核心功能，实现数据从主服务器（Master）自动同步到从服务器（Slave）。

**应用场景**：
- 读写分离（提高性能）
- 数据备份（提高可用性）
- 故障切换（高可用）
- 数据分析（不影响主库）

### 1.2 复制架构

```
┌─────────────────┐
│  Master（主库）  │
│  ┌───────────┐  │
│  │  Binlog   │  │
│  └───────────┘  │
└────────┬────────┘
         │ ① Binlog Dump Thread
         │    发送 Binlog 事件
         ↓
┌─────────────────┐
│  Slave（从库）   │
│  ┌───────────┐  │
│  │ I/O Thread│←─┘ ② 接收并写入 Relay Log
│  └─────┬─────┘  │
│        │        │
│  ┌─────↓─────┐  │
│  │ Relay Log │  │
│  └─────┬─────┘  │
│        │        │
│  ┌─────↓─────┐  │
│  │SQL Thread │  │ ③ 读取并执行 Relay Log
│  └───────────┘  │
└─────────────────┘
```

### 1.3 复制流程

**三个线程**：
1. **Binlog Dump Thread**（主库）：读取 Binlog 并发送给从库
2. **I/O Thread**（从库）：接收 Binlog 并写入 Relay Log
3. **SQL Thread**（从库）：读取 Relay Log 并执行 SQL

**详细步骤**：
```
1. 主库执行 SQL，记录到 Binlog
2. 从库 I/O 线程连接主库，请求 Binlog
3. 主库 Binlog Dump 线程发送 Binlog 事件
4. 从库 I/O 线程接收并写入 Relay Log
5. 从库 SQL 线程读取 Relay Log 并执行
6. 从库数据与主库保持一致
```

## 2. 主从复制配置

### 2.1 环境准备

**服务器规划**：
```
主库（Master）：192.168.1.10
从库1（Slave1）：192.168.1.11
从库2（Slave2）：192.168.1.12
```

**版本要求**：
- 主从 MySQL 版本尽量一致
- 从库版本可以高于主库
- 主库版本不能高于从库

### 2.2 主库配置

**1. 修改配置文件**
```ini
# /etc/my.cnf 或 /etc/mysql/my.cnf
[mysqld]
# 服务器 ID（唯一）
server-id = 1

# 开启 Binlog
log-bin = mysql-bin

# Binlog 格式（推荐 ROW）
binlog-format = ROW

# 要复制的数据库（可选）
binlog-do-db = mydb

# 不复制的数据库（可选）
binlog-ignore-db = mysql
binlog-ignore-db = information_schema
binlog-ignore-db = performance_schema
binlog-ignore-db = sys

# Binlog 过期时间（天）
expire-logs-days = 7

# 每次事务提交同步 Binlog
sync-binlog = 1
```

**2. 重启 MySQL**
```bash
systemctl restart mysqld
```

**3. 创建复制用户**
```sql
-- 登录主库
mysql -u root -p

-- 创建复制用户
CREATE USER 'repl'@'192.168.1.%' IDENTIFIED BY 'Repl@123456';

-- 授予复制权限
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'192.168.1.%';

-- 刷新权限
FLUSH PRIVILEGES;

-- 查看主库状态
SHOW MASTER STATUS;
```

**输出示例**：
```
+------------------+----------+--------------+------------------+
| File             | Position | Binlog_Do_DB | Binlog_Ignore_DB |
+------------------+----------+--------------+------------------+
| mysql-bin.000001 |      154 | mydb         | mysql,...        |
+------------------+----------+--------------+------------------+
```

### 2.3 从库配置

**1. 修改配置文件**
```ini
# /etc/my.cnf
[mysqld]
# 服务器 ID（唯一，不能与主库相同）
server-id = 2

# 开启 Relay Log
relay-log = mysql-relay-bin

# 只读模式（可选，防止从库被写入）
read-only = 1

# 超级用户可以写入（配合 read-only）
super-read-only = 1

# 从库更新也记录 Binlog（级联复制需要）
log-slave-updates = 1

# 跳过复制错误（谨慎使用）
# slave-skip-errors = 1062,1032
```

**2. 重启 MySQL**
```bash
systemctl restart mysqld
```

**3. 配置主从关系**
```sql
-- 登录从库
mysql -u root -p

-- 停止从库（如果已经运行）
STOP SLAVE;

-- 配置主库信息
CHANGE MASTER TO
    MASTER_HOST='192.168.1.10',
    MASTER_USER='repl',
    MASTER_PASSWORD='Repl@123456',
    MASTER_LOG_FILE='mysql-bin.000001',
    MASTER_LOG_POS=154;

-- 启动从库
START SLAVE;

-- 查看从库状态
SHOW SLAVE STATUS\G
```

**4. 检查复制状态**
```sql
SHOW SLAVE STATUS\G

-- 关键字段
-- Slave_IO_Running: Yes（I/O 线程运行正常）
-- Slave_SQL_Running: Yes（SQL 线程运行正常）
-- Seconds_Behind_Master: 0（主从延迟秒数）
-- Last_IO_Error: （I/O 错误信息）
-- Last_SQL_Error: （SQL 错误信息）
```

### 2.4 测试主从复制

**在主库创建测试数据**：
```sql
-- 主库操作

USE test_repl;
```

## 3. 半同步复制

### 3.1 异步复制 vs 半同步复制

**异步复制（默认）**：
```
主库执行事务 → 写入 Binlog → 立即返回客户端
                              ↓
                         异步发送给从库
```
- 优点：性能好
- 缺点：主库宕机可能丢失数据

**半同步复制**：
```
主库执行事务 → 写入 Binlog → 等待至少一个从库确认 → 返回客户端
```
- 优点：数据更安全
- 缺点：性能略差

### 3.2 配置半同步复制

**1. 安装插件（主库和从库）**
```sql
-- 主库安装
INSTALL PLUGIN rpl_semi_sync_master SONAME 'semisync_master.so';

-- 从库安装
INSTALL PLUGIN rpl_semi_sync_slave SONAME 'semisync_slave.so';

-- 查看插件
SHOW PLUGINS;
```

**2. 主库配置**
```sql
-- 开启半同步复制
SET GLOBAL rpl_semi_sync_master_enabled = 1;

-- 超时时间（毫秒）
SET GLOBAL rpl_semi_sync_master_timeout = 1000;

-- 查看状态
SHOW VARIABLES LIKE 'rpl_semi_sync%';
SHOW STATUS LIKE 'Rpl_semi_sync%';
```

**3. 从库配置**
```sql
-- 开启半同步复制
SET GLOBAL rpl_semi_sync_slave_enabled = 1;

-- 重启从库复制
STOP SLAVE IO_THREAD;
START SLAVE IO_THREAD;

-- 查看状态
SHOW STATUS LIKE 'Rpl_semi_sync%';
```

**4. 配置文件持久化**
```ini
# 主库 my.cnf
[mysqld]
rpl_semi_sync_master_enabled = 1
rpl_semi_sync_master_timeout = 1000

# 从库 my.cnf
[mysqld]
rpl_semi_sync_slave_enabled = 1
```

## 4. GTID 复制

### 4.1 什么是 GTID

GTID（Global Transaction Identifier）是全局事务标识符，每个事务都有唯一的 GTID。

**格式**：
```
GTID = server_uuid:transaction_id
示例：3E11FA47-71CA-11E1-9E33-C80AA9429562:23
```

**优点**：
- 自动故障转移
- 简化主从切换
- 避免重复执行事务

### 4.2 配置 GTID 复制

**1. 主库配置**
```ini
# my.cnf
[mysqld]
server-id = 1
log-bin = mysql-bin
binlog-format = ROW

# 开启 GTID
gtid-mode = ON
enforce-gtid-consistency = ON

# 从库更新记录 Binlog
log-slave-updates = 1
```

**2. 从库配置**
```ini
# my.cnf
[mysqld]
server-id = 2
relay-log = mysql-relay-bin

# 开启 GTID
gtid-mode = ON
enforce-gtid-consistency = ON
log-slave-updates = 1
```

**3. 重启主从库**
```bash
systemctl restart mysqld
```

**4. 配置主从关系（使用 GTID）**
```sql
-- 从库操作
STOP SLAVE;

CHANGE MASTER TO
    MASTER_HOST='192.168.1.10',
    MASTER_USER='repl',
    MASTER_PASSWORD='Repl@123456',
    MASTER_AUTO_POSITION=1;  -- 使用 GTID 自动定位

START SLAVE;

SHOW SLAVE STATUS\G
```

**5. 查看 GTID 信息**
```sql
-- 查看已执行的 GTID
SHOW GLOBAL VARIABLES LIKE 'gtid_executed';

-- 查看已清除的 GTID
SHOW GLOBAL VARIABLES LIKE 'gtid_purged';
```

## 5. 读写分离

### 5.1 读写分离架构

```
┌──────────────┐
│   应用程序    │
└──────┬───────┘
       │
┌──────↓───────────────────────┐
│      数据库中间件              │
│   (ProxySQL / MaxScale)      │
└──────┬───────────────────────┘
       │
       ├─────────┬─────────┐
       ↓         ↓         ↓
┌──────────┐ ┌──────────┐ ┌──────────┐
│  Master  │ │ Slave1   │ │ Slave2   │
│  (写)    │ │  (读)    │ │  (读)    │
└──────────┘ └──────────┘ └──────────┘
```

### 5.2 使用 ProxySQL 实现读写分离

**1. 安装 ProxySQL**
```bash
# CentOS/RHEL
yum install -y proxysql

# Ubuntu/Debian
apt-get install -y proxysql

# 启动 ProxySQL
systemctl start proxysql
systemctl enable proxysql
```

**2. 配置 ProxySQL**
```bash
# 登录 ProxySQL 管理端口
mysql -u admin -padmin -h 127.0.0.1 -P6032

-- 添加 MySQL 服务器
INSERT INTO mysql_servers(hostgroup_id, hostname, port) 
VALUES (1, '192.168.1.10', 3306);  -- 主库（写）

INSERT INTO mysql_servers(hostgroup_id, hostname, port) 
VALUES (2, '192.168.1.11', 3306);  -- 从库1（读）

INSERT INTO mysql_servers(hostgroup_id, hostname, port) 
VALUES (2, '192.168.1.12', 3306);  -- 从库2（读）

-- 加载配置
LOAD MYSQL SERVERS TO RUNTIME;
SAVE MYSQL SERVERS TO DISK;

-- 添加监控用户
INSERT INTO mysql_users(username, password, default_hostgroup)
VALUES ('proxyuser', 'ProxyPass@123', 1);

LOAD MYSQL USERS TO RUNTIME;
SAVE MYSQL USERS TO DISK;

-- 配置读写分离规则
INSERT INTO mysql_query_rules(rule_id, active, match_pattern, destination_hostgroup, apply)
VALUES (1, 1, '^SELECT.*FOR UPDATE$', 1, 1);  -- SELECT FOR UPDATE 走主库

INSERT INTO mysql_query_rules(rule_id, active, match_pattern, destination_hostgroup, apply)
VALUES (2, 1, '^SELECT', 2, 1);  -- SELECT 走从库

LOAD MYSQL QUERY RULES TO RUNTIME;
SAVE MYSQL QUERY RULES TO DISK;
```

**3. 应用程序连接 ProxySQL**
```python
# Python 示例
import pymysql

# 连接 ProxySQL（默认端口 6033）
conn = pymysql.connect(
    host='127.0.0.1',
    port=6033,
    user='proxyuser',
    password='ProxyPass@123',
    database='test_repl'
)

cursor = conn.cursor()

# 写操作（自动路由到主库）
cursor.execute("INSERT INTO users (username) VALUES ('user4')")
conn.commit()

# 读操作（自动路由到从库）
cursor.execute("SELECT * FROM users")
results = cursor.fetchall()
print(results)

cursor.close()
conn.close()
```

### 5.3 应用层读写分离

```python
# Python 示例：应用层实现读写分离
class DatabaseRouter:
    def __init__(self):
        # 主库连接
        self.master = pymysql.connect(
            host='192.168.1.10',
            user='root',
            password='password',
            database='test_repl'
        )
        
        # 从库连接池
        self.slaves = [
            pymysql.connect(host='192.168.1.11', user='root', password='password', database='test_repl'),
            pymysql.connect(host='192.168.1.12', user='root', password='password', database='test_repl')
        ]
        self.slave_index = 0
    
    def get_write_connection(self):
        """获取写连接（主库）"""
        return self.master
    
    def get_read_connection(self):
        """获取读连接（从库，轮询）"""
        conn = self.slaves[self.slave_index]
        self.slave_index = (self.slave_index + 1) % len(self.slaves)
        return conn

# 使用示例
router = DatabaseRouter()

# 写操作
write_conn = router.get_write_connection()
cursor = write_conn.cursor()
cursor.execute("INSERT INTO users (username) VALUES ('user5')")
write_conn.commit()

# 读操作
read_conn = router.get_read_connection()
cursor = read_conn.cursor()
cursor.execute("SELECT * FROM users")
results = cursor.fetchall()
```

## 6. 主从延迟问题

### 6.1 延迟原因

1. **从库性能不足**：硬件配置低于主库
2. **大事务**：主库执行大事务，从库回放慢
3. **网络延迟**：主从之间网络不稳定
4. **单线程回放**：从库 SQL 线程单线程执行
5. **锁等待**：从库执行时遇到锁等待

### 6.2 查看延迟

```sql
-- 从库查看延迟
SHOW SLAVE STATUS\G

-- 关键字段
-- Seconds_Behind_Master: 延迟秒数
--   0: 无延迟
--   NULL: 复制未运行或出错
--   >0: 延迟秒数

-- 查看复制延迟详情
SELECT 
    CHANNEL_NAME,
    SERVICE_STATE,
    LAST_ERROR_NUMBER,
    LAST_ERROR_MESSAGE,
    LAST_ERROR_TIMESTAMP
FROM performance_schema.replication_connection_status;
```

### 6.3 解决延迟

**1. 并行复制（MySQL 5.7+）**
```sql
-- 从库配置
STOP SLAVE;

-- 设置并行复制
SET GLOBAL slave_parallel_type = 'LOGICAL_CLOCK';
SET GLOBAL slave_parallel_workers = 4;  -- 并行线程数

START SLAVE;

-- 查看并行复制状态
SHOW PROCESSLIST;
```

**配置文件**：
```ini
# my.cnf
[mysqld]
slave_parallel_type = LOGICAL_CLOCK
slave_parallel_workers = 4
```

**2. 优化大事务**
```sql
-- ❌ 避免大事务
START TRANSACTION;
UPDATE users SET status = 1;  -- 更新百万行
COMMIT;

-- ✅ 分批处理
DELIMITER $$
CREATE PROCEDURE batch_update()
BEGIN
    DECLARE done INT DEFAULT 0;
    DECLARE batch_size INT DEFAULT 1000;
    
    WHILE done = 0 DO
        UPDATE users SET status = 1 
        WHERE status = 0 
        LIMIT batch_size;
        
        IF ROW_COUNT() < batch_size THEN
            SET done = 1;
        END IF;
        
        -- 提交小事务
        COMMIT;
    END WHILE;
END$$
DELIMITER ;
```

**3. 提升从库性能**
```ini
# 从库优化配置
[mysqld]
# 增大缓冲池
innodb_buffer_pool_size = 8G

# 增大日志缓冲
innodb_log_buffer_size = 32M

# 调整刷新策略
innodb_flush_log_at_trx_commit = 2

# 禁用 Binlog（如果不需要级联复制）
skip-log-bin
```

**4. 监控和告警**
```sql
-- 创建监控脚本
#!/bin/bash
DELAY=$(mysql -u root -p'password' -e "SHOW SLAVE STATUS\G" | grep "Seconds_Behind_Master" | awk '{print $2}')

if [ "$DELAY" -gt 10 ]; then
    echo "主从延迟超过 10 秒：$DELAY 秒" | mail -s "MySQL 主从延迟告警" admin@example.com
fi
```

## 7. 故障处理

### 7.1 常见错误

**错误1：1062 - Duplicate entry**
```sql
-- 查看错误
SHOW SLAVE STATUS\G
-- Last_SQL_Error: Error 'Duplicate entry '1' for key 'PRIMARY'' on query

-- 解决方法1：跳过错误
STOP SLAVE;
SET GLOBAL sql_slave_skip_counter = 1;
START SLAVE;

-- 解决方法2：删除重复数据
-- 在从库手动删除重复记录
DELETE FROM table_name WHERE id = 1;
START SLAVE;
```

**错误2：1032 - Can't find record**
```sql
-- 错误：找不到要更新/删除的记录
-- 解决：跳过错误或手动插入缺失数据
STOP SLAVE;
SET GLOBAL sql_slave_skip_counter = 1;
START SLAVE;
```

**错误3：主从位置不一致**
```sql
-- 重新同步
STOP SLAVE;

-- 方法1：从主库当前位置开始
SHOW MASTER STATUS;  -- 在主库执行
CHANGE MASTER TO MASTER_LOG_FILE='mysql-bin.000002', MASTER_LOG_POS=154;

-- 方法2：使用 GTID（如果开启）
RESET SLAVE;
CHANGE MASTER TO MASTER_AUTO_POSITION=1;

START SLAVE;
```

### 7.2 主从切换

**场景：主库故障，提升从库为主库**

**1. 停止从库复制**
```sql
-- 在从库执行
STOP SLAVE;
RESET SLAVE ALL;
```

**2. 提升从库为主库**
```sql
-- 关闭只读模式
SET GLOBAL read_only = 0;
SET GLOBAL super_read_only = 0;

-- 开启 Binlog（如果未开启）
-- 修改 my.cnf，重启 MySQL
```

**3. 其他从库指向新主库**
```sql
-- 在其他从库执行
STOP SLAVE;

CHANGE MASTER TO
    MASTER_HOST='192.168.1.11',  -- 新主库 IP
    MASTER_USER='repl',
    MASTER_PASSWORD='Repl@123456',
    MASTER_AUTO_POSITION=1;  -- 使用 GTID

START SLAVE;
```

**4. 应用程序切换**
```python
# 更新应用程序配置，指向新主库
DATABASE_HOST = '192.168.1.11'  # 新主库
```

### 案例2：监控主从状态

```python
#!/usr/bin/env python3
import pymysql
import time

def check_replication_status(host, user, password):
    try:
        conn = pymysql.connect(host=host, user=user, password=password)
        cursor = conn.cursor(pymysql.cursors.DictCursor)
        cursor.execute("SHOW SLAVE STATUS")
        status = cursor.fetchone()
        
        if status:
            io_running = status['Slave_IO_Running']
            sql_running = status['Slave_SQL_Running']
            delay = status['Seconds_Behind_Master']
            
            print(f"主机: {host}")
            print(f"  I/O 线程: {io_running}")
            print(f"  SQL 线程: {sql_running}")
            print(f"  延迟: {delay} 秒")
            
            if io_running != 'Yes' or sql_running != 'Yes':
                print(f"  ⚠️ 警告：复制未正常运行！")
            elif delay and delay > 10:

            print(f"主机: {host} - 未配置主从复制")
        
        cursor.close()
        conn.close()
    except Exception as e:
        print(f"主机: {host} - 连接失败: {e}")
```

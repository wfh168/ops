## 1. 分库分表概述

### 1.1 为什么需要分库分表

**单库单表的问题**：
```
数据量过大：
- 单表数据超过 1000 万，查询变慢
- 索引文件过大，内存放不下
- 备份恢复时间长

并发量过大：
- 连接数不够
- CPU、内存、I/O 瓶颈
- 锁竞争严重
```

**分库分表的好处**：
```
✅ 提高查询性能
✅ 提高并发能力
✅ 降低单库压力
✅ 提高可扩展性
```

### 1.2 分库分表类型

**垂直拆分**：
```
按业务模块拆分
用户库：users, user_profiles
订单库：orders, order_items
商品库：products, categories
```

**水平拆分**：
```
按数据拆分
users_0, users_1, users_2, users_3
orders_2023, orders_2024
```

## 2. 垂直拆分

### 2.1 垂直分库

**拆分前**：
```sql
-- 单个数据库
CREATE DATABASE ecommerce;

USE ecommerce;
CREATE TABLE users (...);
CREATE TABLE orders (...);
CREATE TABLE products (...);
```

**拆分后**：
```sql
-- 用户库
CREATE DATABASE user_db;
USE user_db;
CREATE TABLE users (...);
CREATE TABLE user_profiles (...);

-- 订单库
CREATE DATABASE order_db;
USE order_db;
CREATE TABLE orders (...);
CREATE TABLE order_items (...);

-- 商品库
CREATE DATABASE product_db;
USE product_db;
CREATE TABLE products (...);
CREATE TABLE categories (...);
```

**优点**：
- 业务隔离，互不影响
- 便于维护和扩展
- 可以针对不同业务优化

**缺点**：
- 跨库 JOIN 困难
- 分布式事务复杂
- 数据一致性难保证

### 2.2 垂直分表

**拆分前**：
```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100),
    password VARCHAR(255),
    profile TEXT,        -- 大字段
    settings JSON,       -- 大字段
    avatar BLOB,         -- 大字段
    created_at DATETIME
);
```

**拆分后**：
```sql
-- 主表（常用字段）
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100),
    password VARCHAR(255),
    created_at DATETIME
);

-- 扩展表（不常用字段）
CREATE TABLE user_profiles (
    user_id INT PRIMARY KEY,
    profile TEXT,
    settings JSON,
    avatar BLOB,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

## 3. 水平拆分

### 3.1 水平分库

**拆分策略**：
```sql
-- 按用户 ID 取模分库
user_id % 4 = 0 → user_db_0
user_id % 4 = 1 → user_db_1
user_id % 4 = 2 → user_db_2
user_id % 4 = 3 → user_db_3
```

**创建分库**：
```sql
CREATE DATABASE user_db_0;
CREATE DATABASE user_db_1;
CREATE DATABASE user_db_2;
CREATE DATABASE user_db_3;

-- 每个库中创建相同的表结构
USE user_db_0;
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100),
    created_at DATETIME
);
```

### 3.2 水平分表

**按范围分表**：
```sql
-- 按时间分表
CREATE TABLE orders_2023_01 (...);
CREATE TABLE orders_2023_02 (...);
CREATE TABLE orders_2024_01 (...);
CREATE TABLE orders_2024_02 (...);
```

**按哈希分表**：
```sql
-- 按 ID 取模分表
CREATE TABLE users_0 (...);  -- id % 4 = 0
CREATE TABLE users_1 (...);  -- id % 4 = 1
CREATE TABLE users_2 (...);  -- id % 4 = 2
CREATE TABLE users_3 (...);  -- id % 4 = 3
```

## 4. 分片策略

### 4.1 范围分片

**按时间范围**：
```python
def get_table_name(date):
    year_month = date.strftime('%Y_%m')
    return f"orders_{year_month}"

# 示例
date = datetime(2024, 1, 15)
table = get_table_name(date)  # orders_2024_01
```

**按 ID 范围**：
```python
def get_table_name(user_id):
    if user_id < 1000000:
        return "users_0"
    elif user_id < 2000000:
        return "users_1"
    elif user_id < 3000000:
        return "users_2"
    else:
        return "users_3"
```

**优点**：
- 扩容简单
- 范围查询方便

**缺点**：
- 数据分布可能不均匀
- 热点问题

### 4.2 哈希分片

**取模分片**：
```python
def get_table_name(user_id, shard_count=4):
    shard_index = user_id % shard_count
    return f"users_{shard_index}"

# 示例
table = get_table_name(12345, 4)  # users_1
```

**一致性哈希**：
```python
import hashlib

def consistent_hash(key, shard_count=4):
    hash_value = int(hashlib.md5(str(key).encode()).hexdigest(), 16)
    shard_index = hash_value % shard_count
    return f"users_{shard_index}"
```

**优点**：
- 数据分布均匀
- 避免热点问题

**缺点**：
- 范围查询困难
- 扩容需要数据迁移

### 4.3 地理位置分片

```python
def get_db_name(city):
    region_map = {
        '北京': 'db_north',
        '上海': 'db_east',
        '广州': 'db_south',
        '成都': 'db_west'
    }
    return region_map.get(city, 'db_default')
```

## 5. ShardingSphere

### 5.1 ShardingSphere 简介

ShardingSphere 是 Apache 的分库分表中间件。

**组件**：
- **ShardingSphere-JDBC**：客户端分片
- **ShardingSphere-Proxy**：代理服务器分片
- **ShardingSphere-Sidecar**：Service Mesh 分片

### 5.2 ShardingSphere-JDBC 配置

**添加依赖**：
```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.apache.shardingsphere</groupId>
    <artifactId>shardingsphere-jdbc-core-spring-boot-starter</artifactId>
    <version>5.3.0</version>
</dependency>
```

**配置文件**：
```yaml
# application.yml
spring:
  shardingsphere:
    datasource:
      names: ds0,ds1,ds2,ds3
      ds0:
        type: com.zaxxer.hikari.HikariDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        jdbc-url: jdbc:mysql://localhost:3306/user_db_0
        username: root
        password: password
      ds1:
        type: com.zaxxer.hikari.HikariDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        jdbc-url: jdbc:mysql://localhost:3306/user_db_1
        username: root
        password: password
      ds2:
        type: com.zaxxer.hikari.HikariDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        jdbc-url: jdbc:mysql://localhost:3306/user_db_2
        username: root
        password: password
      ds3:
        type: com.zaxxer.hikari.HikariDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        jdbc-url: jdbc:mysql://localhost:3306/user_db_3
        username: root
        password: password
    
    rules:
      sharding:
        tables:
          users:
            actual-data-nodes: ds$->{0..3}.users
            database-strategy:
              standard:
                sharding-column: id
                sharding-algorithm-name: user-db-inline
            key-generate-strategy:
              column: id
              key-generator-name: snowflake
        
        sharding-algorithms:
          user-db-inline:
            type: INLINE
            props:
              algorithm-expression: ds$->{id % 4}
        
        key-generators:
          snowflake:
            type: SNOWFLAKE
    
    props:
      sql-show: true
```

**使用示例**：
```java
@Service
public class UserService {
    @Autowired
    private UserMapper userMapper;
    
    public void createUser(User user) {
        // ShardingSphere 自动路由到正确的分片
        userMapper.insert(user);
    }
    
    public User getUser(Long id) {
        // 根据 ID 路由到对应分片
        return userMapper.selectById(id);
    }
    
    public List<User> getAllUsers() {
        // 查询所有分片并合并结果
        return userMapper.selectList(null);
    }
}
```

## 7. 分布式事务

### 7.1 分布式事务问题

**跨库事务**：
```sql
-- 用户库
BEGIN;
UPDATE user_db_0.users SET balance = balance - 100 WHERE id = 1;

-- 订单库
INSERT INTO order_db.orders (user_id, amount) VALUES (1, 100);

COMMIT;  -- 如何保证两个库的事务一致性？
```

### 7.2 解决方案

**1. 两阶段提交（2PC）**：
```
准备阶段：
- 协调者询问所有参与者是否可以提交
- 参与者执行事务但不提交

提交阶段：
- 所有参与者都同意，协调者发送提交命令
- 任一参与者拒绝，协调者发送回滚命令
```

**2. TCC（Try-Confirm-Cancel）**：
```java
// Try 阶段：尝试执行，预留资源
public void tryTransfer(Long fromUserId, Long toUserId, BigDecimal amount) {
    // 冻结转出账户金额
    accountService.freeze(fromUserId, amount);
}

// Confirm 阶段：确认执行
public void confirmTransfer(Long fromUserId, Long toUserId, BigDecimal amount) {
    // 扣减转出账户
    accountService.deduct(fromUserId, amount);
    // 增加转入账户
    accountService.add(toUserId, amount);
}

// Cancel 阶段：取消执行
public void cancelTransfer(Long fromUserId, Long toUserId, BigDecimal amount) {
    // 解冻转出账户金额
    accountService.unfreeze(fromUserId, amount);
}
```

**3. 本地消息表**：
```sql
-- 本地消息表
CREATE TABLE local_message (
    id BIGINT PRIMARY KEY,
    content TEXT,
    status VARCHAR(20),  -- PENDING, SUCCESS, FAIL
    retry_count INT DEFAULT 0,
    created_at DATETIME
);

-- 业务表和消息表在同一个库，使用本地事务
BEGIN;
INSERT INTO orders (...);
INSERT INTO local_message (content, status) VALUES ('...', 'PENDING');
COMMIT;

-- 定时任务扫描消息表，发送消息
-- 消费者处理消息，更新消息状态
```

**4. 最终一致性**：
```
- 不追求强一致性
- 通过补偿机制达到最终一致
- 适合大多数业务场景
```

```python
def create_user(user_data):
```

### 案例1：电商订单分库分表

```yaml
# 分片策略
# - 按用户 ID 分库（4 个库）
# - 按订单时间分表（按月）

# 配置
spring:
  shardingsphere:
    datasource:
      names: ds0,ds1,ds2,ds3

      sharding:

              standard:

            props:

            type: INTERVAL
            props:

              datetime-lower: 2024-01-01 00:00:00
              datetime-upper: 2024-12-31 23:59:59
              sharding-suffix-pattern: yyyyMM
              datetime-interval-amount: 1
              datetime-interval-unit: MONTHS
```

### 案例2：用户表分片

```python
# 应用层分片
class UserSharding:
    def __init__(self):
        self.shard_count = 4
        self.connections = {
            0: pymysql.connect(host='localhost', db='user_db_0', ...),
            1: pymysql.connect(host='localhost', db='user_db_1', ...),
            2: pymysql.connect(host='localhost', db='user_db_2', ...),
            3: pymysql.connect(host='localhost', db='user_db_3', ...)
        }
    
    def get_shard_index(self, user_id):
        return user_id % self.shard_count
    
    def get_connection(self, user_id):
        shard_index = self.get_shard_index(user_id)
        return self.connections[shard_index]
    
    def insert_user(self, user_id, username, email):
        conn = self.get_connection(user_id)
        cursor = conn.cursor()
        cursor.execute(
            "INSERT INTO users (id, username, email) VALUES (%s, %s, %s)",
            (user_id, username, email)
        )
        conn.commit()
    
    def get_user(self, user_id):
        conn = self.get_connection(user_id)
        cursor = conn.cursor()
        cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
        return cursor.fetchone()
```

## 1. 备份策略

### 1.1 备份类型

**按备份方式分类**：
- **逻辑备份**：导出 SQL 语句（mysqldump）
- **物理备份**：复制数据文件（XtraBackup）

**按备份内容分类**：
- **全量备份**：备份所有数据
- **增量备份**：备份变化的数据
- **差异备份**：备份自上次全量备份后的变化

**按备份时机分类**：
- **热备份**：在线备份，不停机
- **温备份**：锁表备份，只读
- **冷备份**：停机备份

### 1.2 备份策略设计

**3-2-1 原则**：
```
3 份数据副本
2 种不同存储介质
1 份异地备份
```

**备份周期**：
```
每天：增量备份
每周：全量备份
每月：归档备份
```

**示例策略**：
```
周日：全量备份
周一至周六：增量备份
保留周期：30 天
异地备份：每周同步到云存储
```

## 2. mysqldump 逻辑备份

### 2.1 基本用法

**备份单个数据库**：
```bash
# 备份数据库
mysqldump -u root -p mydb > mydb_backup.sql

# 备份数据库（带创建数据库语句）
mysqldump -u root -p --databases mydb > mydb_backup.sql

# 备份多个数据库
mysqldump -u root -p --databases db1 db2 db3 > multi_db_backup.sql

# 备份所有数据库
mysqldump -u root -p --all-databases > all_db_backup.sql
```

**备份单个表**：
```bash
# 备份单个表
mysqldump -u root -p mydb users > users_backup.sql

# 备份多个表
mysqldump -u root -p mydb users orders > tables_backup.sql
```

### 2.2 常用选项

```bash
# 完整备份命令
mysqldump -u root -p \
    --single-transaction \     # InnoDB 一致性备份
    --routines \               # 备份存储过程和函数
    --triggers \               # 备份触发器
    --events \                 # 备份事件
    --master-data=2 \          # 记录 Binlog 位置
    --flush-logs \             # 刷新日志
    --hex-blob \               # 二进制数据用十六进制
    --default-character-set=utf8mb4 \
    --databases mydb > mydb_full_backup.sql

# 只备份表结构
mysqldump -u root -p --no-data mydb > mydb_schema.sql

# 只备份数据
mysqldump -u root -p --no-create-info mydb > mydb_data.sql

# 压缩备份
mysqldump -u root -p mydb | gzip > mydb_backup.sql.gz
```

### 2.3 备份脚本

```bash
#!/bin/bash
# mysql_backup.sh

# 配置
MYSQL_USER="root"
MYSQL_PASS="password"
BACKUP_DIR="/backup/mysql"
DATE=$(date +%Y%m%d_%H%M%S)
KEEP_DAYS=30

# 创建备份目录
mkdir -p $BACKUP_DIR

# 全量备份
mysqldump -u$MYSQL_USER -p$MYSQL_PASS \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --master-data=2 \
    --all-databases | gzip > $BACKUP_DIR/full_backup_$DATE.sql.gz

# 检查备份结果
if [ $? -eq 0 ]; then
    echo "备份成功: full_backup_$DATE.sql.gz"
else
    echo "备份失败！"
    exit 1
fi

# 删除旧备份
find $BACKUP_DIR -name "full_backup_*.sql.gz" -mtime +$KEEP_DAYS -delete

# 上传到云存储（可选）
# aws s3 cp $BACKUP_DIR/full_backup_$DATE.sql.gz s3://my-backup-bucket/
```

### 2.4 恢复数据

```bash
# 恢复数据库
mysql -u root -p mydb < mydb_backup.sql

# 恢复压缩备份
gunzip < mydb_backup.sql.gz | mysql -u root -p mydb

# 恢复所有数据库
mysql -u root -p < all_db_backup.sql

# 恢复时显示进度
pv mydb_backup.sql | mysql -u root -p mydb
```

## 3. XtraBackup 物理备份

### 3.1 安装 XtraBackup

```bash
# CentOS/RHEL
yum install -y percona-xtrabackup-80

# Ubuntu/Debian
apt-get install -y percona-xtrabackup-80

# 验证安装
xtrabackup --version
```

### 3.2 全量备份

```bash
# 全量备份
xtrabackup --backup \
    --user=root \
    --password=password \
    --target-dir=/backup/full_backup

# 备份完成后准备
xtrabackup --prepare \
    --target-dir=/backup/full_backup

# 查看备份信息
cat /backup/full_backup/xtrabackup_checkpoints
```

### 3.3 增量备份

```bash
# 1. 全量备份
xtrabackup --backup \
    --user=root \
    --password=password \
    --target-dir=/backup/full

# 2. 第一次增量备份
xtrabackup --backup \
    --user=root \
    --password=password \
    --target-dir=/backup/inc1 \
    --incremental-basedir=/backup/full

# 3. 第二次增量备份
xtrabackup --backup \
    --user=root \
    --password=password \
    --target-dir=/backup/inc2 \
    --incremental-basedir=/backup/inc1

# 4. 准备恢复
# 准备全量备份
xtrabackup --prepare --apply-log-only \
    --target-dir=/backup/full

# 应用第一次增量
xtrabackup --prepare --apply-log-only \
    --target-dir=/backup/full \
    --incremental-dir=/backup/inc1

# 应用第二次增量
xtrabackup --prepare \
    --target-dir=/backup/full \
    --incremental-dir=/backup/inc2
```

### 3.4 恢复数据

```bash
# 1. 停止 MySQL
systemctl stop mysqld

# 2. 清空数据目录
rm -rf /var/lib/mysql/*

# 3. 恢复数据
xtrabackup --copy-back \
    --target-dir=/backup/full_backup

# 4. 修改权限
chown -R mysql:mysql /var/lib/mysql

# 5. 启动 MySQL
systemctl start mysqld
```

### 3.5 备份脚本

```bash
#!/bin/bash
# xtrabackup_backup.sh

MYSQL_USER="root"
MYSQL_PASS="password"
BACKUP_DIR="/backup/xtrabackup"
DATE=$(date +%Y%m%d)
FULL_BACKUP_DIR="$BACKUP_DIR/full_$DATE"
KEEP_DAYS=7

# 创建备份目录
mkdir -p $BACKUP_DIR

# 判断是否需要全量备份（每周日）
if [ $(date +%u) -eq 7 ]; then
    # 全量备份
    xtrabackup --backup \
        --user=$MYSQL_USER \
        --password=$MYSQL_PASS \
        --target-dir=$FULL_BACKUP_DIR
    
    echo "全量备份完成: $FULL_BACKUP_DIR"
else
    # 增量备份
    LAST_FULL=$(ls -td $BACKUP_DIR/full_* | head -1)
    LAST_INC=$(ls -td $BACKUP_DIR/inc_* 2>/dev/null | head -1)
    
    if [ -n "$LAST_INC" ]; then
        BASE_DIR=$LAST_INC
    else
        BASE_DIR=$LAST_FULL
    fi
    
    INC_BACKUP_DIR="$BACKUP_DIR/inc_$DATE"
    
    xtrabackup --backup \
        --user=$MYSQL_USER \
        --password=$MYSQL_PASS \
        --target-dir=$INC_BACKUP_DIR \
        --incremental-basedir=$BASE_DIR
    
    echo "增量备份完成: $INC_BACKUP_DIR"
fi

# 删除旧备份
find $BACKUP_DIR -name "full_*" -mtime +$KEEP_DAYS -exec rm -rf {} \;
find $BACKUP_DIR -name "inc_*" -mtime +$KEEP_DAYS -exec rm -rf {} \;
```

## 4. Binlog 备份

### 4.1 Binlog 配置

```ini
# my.cnf
[mysqld]
log_bin = mysql-bin
binlog_format = ROW
expire_logs_days = 7
max_binlog_size = 1G
```

### 4.2 备份 Binlog

```bash
# 查看 Binlog 列表
mysql -u root -p -e "SHOW BINARY LOGS"

# 刷新 Binlog
mysql -u root -p -e "FLUSH LOGS"

# 备份 Binlog
cp /var/lib/mysql/mysql-bin.* /backup/binlog/

# 定期备份脚本
#!/bin/bash
BINLOG_DIR="/var/lib/mysql"
BACKUP_DIR="/backup/binlog"
DATE=$(date +%Y%m%d)

# 刷新日志
mysql -u root -p'password' -e "FLUSH LOGS"

# 复制 Binlog
rsync -av --exclude='mysql-bin.index' \
    $BINLOG_DIR/mysql-bin.* $BACKUP_DIR/

# 压缩旧日志
find $BACKUP_DIR -name "mysql-bin.*" -mtime +1 -exec gzip {} \;
```

### 4.3 使用 Binlog 恢复

```bash
# 查看 Binlog 内容
mysqlbinlog mysql-bin.000001

# 恢复指定时间范围
mysqlbinlog --start-datetime="2024-01-01 00:00:00" \
            --stop-datetime="2024-01-01 23:59:59" \
            mysql-bin.000001 | mysql -u root -p

# 恢复指定位置范围
mysqlbinlog --start-position=154 \
            --stop-position=1024 \
            mysql-bin.000001 | mysql -u root -p

# 跳过错误事件
mysqlbinlog --start-position=154 \
            --stop-position=500 \
            mysql-bin.000001 | mysql -u root -p

mysqlbinlog --start-position=600 \
            mysql-bin.000001 | mysql -u root -p
```

## 6. 灾难恢复

### 6.1 完整恢复流程

```bash
# 场景：数据库服务器故障，需要完全恢复

# 1. 准备新服务器
# 2. 安装 MySQL
yum install -y mysql-server

# 3. 恢复全量备份
xtrabackup --copy-back --target-dir=/backup/full_backup
chown -R mysql:mysql /var/lib/mysql

# 4. 启动 MySQL
systemctl start mysqld

# 5. 应用 Binlog（恢复到故障前）
mysqlbinlog --start-position=154 \
    /backup/binlog/mysql-bin.000010 \
    /backup/binlog/mysql-bin.000011 | mysql -u root -p

# 6. 验证数据
mysql -u root -p -e "SELECT COUNT(*) FROM mydb.users"

# 7. 切换应用
# 更新应用配置，指向新数据库
```

### 6.2 误删除数据恢复

```bash
# 场景：误删除了重要数据

# 1. 立即停止应用，防止更多操作

# 2. 找到删除操作的 Binlog 位置
mysqlbinlog mysql-bin.000001 | grep -i "DELETE FROM users"

# 3. 恢复到删除前的状态
mysqlbinlog --stop-position=1024 mysql-bin.000001 | mysql -u root -p

# 4. 跳过删除操作，继续恢复后续数据
mysqlbinlog --start-position=1500 mysql-bin.000001 | mysql -u root -p

# 5. 验证数据
mysql -u root -p -e "SELECT * FROM users WHERE id = 100"
```

## 7. 云备份

### 7.1 备份到阿里云 OSS

```bash
#!/bin/bash
# backup_to_oss.sh

# 安装 ossutil
wget http://gosspublic.alicdn.com/ossutil/1.7.0/ossutil64
chmod +x ossutil64
mv ossutil64 /usr/local/bin/ossutil

# 配置 OSS
ossutil config -e oss-cn-hangzhou.aliyuncs.com \
    -i YOUR_ACCESS_KEY_ID \
    -k YOUR_ACCESS_KEY_SECRET

# 备份并上传
DATE=$(date +%Y%m%d)
BACKUP_FILE="mysql_backup_$DATE.sql.gz"

mysqldump -u root -p'password' --all-databases | gzip > /tmp/$BACKUP_FILE

ossutil cp /tmp/$BACKUP_FILE oss://my-backup-bucket/mysql/$BACKUP_FILE

rm -f /tmp/$BACKUP_FILE
```

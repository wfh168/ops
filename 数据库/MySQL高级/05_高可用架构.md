## 1. 高可用架构概述

### 1.1 什么是高可用

高可用（High Availability, HA）是指系统能够持续运行，减少停机时间。

**衡量指标**：
```
可用性 = 正常运行时间 / 总时间 × 100%

99.9%（3个9）：年停机时间 8.76 小时
99.99%（4个9）：年停机时间 52.56 分钟
99.999%（5个9）：年停机时间 5.26 分钟
```

### 1.2 高可用架构

```
┌──────────────────────────────────────┐
│          应用层                       │
│    (负载均衡 + 连接池)                 │
└──────────────┬───────────────────────┘
               │
┌──────────────↓───────────────────────┐
│          中间件层                      │
│    (ProxySQL / MaxScale)             │
└──────────────┬───────────────────────┘
               │
       ┌───────┴───────┐
       ↓               ↓
┌─────────────┐  ┌─────────────┐
│   Master    │  │   Master    │
│   (主库)    │←→│   (备库)    │
└──────┬──────┘  └──────┬──────┘
       │                │
   ┌───┴───┐        ┌───┴───┐
   ↓       ↓        ↓       ↓
┌──────┐┌──────┐┌──────┐┌──────┐
│Slave1││Slave2││Slave3││Slave4│
└──────┘└──────┘└──────┘└──────┘
```

## 2. MHA 高可用方案

### 2.1 MHA 架构

MHA（Master High Availability）是 MySQL 高可用解决方案。

**组件**：
- **MHA Manager**：管理节点，监控和故障切换
- **MHA Node**：数据节点，安装在所有 MySQL 服务器

**工作原理**：
```
1. Manager 监控 Master 状态
2. Master 故障时，Manager 自动切换
3. 选择最新的 Slave 提升为 Master
4. 其他 Slave 指向新 Master
5. 应用程序切换到新 Master
```

### 2.5 VIP 切换脚本

```bash
# /usr/local/bin/master_ip_failover
#!/usr/bin/env perl

use strict;
use warnings FATAL => 'all';
use Getopt::Long;

my (
    $command,          $ssh_user,        $orig_master_host, $orig_master_ip,
    $orig_master_port, $new_master_host, $new_master_ip,    $new_master_port
);

my $vip = '192.168.1.100/24';
my $key = '1';
my $ssh_start_vip = "/sbin/ifconfig eth0:$key $vip";
my $ssh_stop_vip = "/sbin/ifconfig eth0:$key down";

GetOptions(
    'command=s'          => \$command,
    'ssh_user=s'         => \$ssh_user,
    'orig_master_host=s' => \$orig_master_host,
    'orig_master_ip=s'   => \$orig_master_ip,
    'orig_master_port=i' => \$orig_master_port,
    'new_master_host=s'  => \$new_master_host,
    'new_master_ip=s'    => \$new_master_ip,
    'new_master_port=i'  => \$new_master_port,
);

exit &main();

sub main {
    if ( $command eq "stop" || $command eq "stopssh" ) {
        my $exit_code = 1;
        eval {
            print "Disabling the VIP on old master: $orig_master_host \n";
            &stop_vip();
            $exit_code = 0;
        };
        if ($@) {
            warn "Got Error: $@\n";
            exit $exit_code;
        }
        exit $exit_code;
    }
    elsif ( $command eq "start" ) {
        my $exit_code = 10;
        eval {
            print "Enabling the VIP - $vip on the new master - $new_master_host \n";
            &start_vip();
            $exit_code = 0;
        };
        if ($@) {
            warn $@;
            exit $exit_code;
        }
        exit $exit_code;
    }
    else {
        &usage();
        exit 1;
    }
}

sub start_vip() {
    `ssh $ssh_user\@$new_master_host \" $ssh_start_vip \"`;
}

sub stop_vip() {
    return 0  unless  ($ssh_user);
    `ssh $ssh_user\@$orig_master_host \" $ssh_stop_vip \"`;
}

sub usage {
    print
    "Usage: master_ip_failover --command=start|stop|stopssh|status --orig_master_host=host --orig_master_ip=ip --orig_master_port=port --new_master_host=host --new_master_ip=ip --new_master_port=port\n";
}
```

## 3. MGR 集群复制

### 3.1 MGR 简介

MGR（MySQL Group Replication）是 MySQL 官方的高可用方案。

**特点**：
- 多主模式或单主模式
- 自动故障检测和切换
- 强一致性保证
- 无需额外组件

### 3.2 配置 MGR

**服务器规划**：
```
Node1: 192.168.1.10
Node2: 192.168.1.11
Node3: 192.168.1.12
```

**配置文件（所有节点）**：
```ini
# my.cnf
[mysqld]
server_id = 1  # 每个节点不同
gtid_mode = ON
enforce_gtid_consistency = ON
binlog_checksum = NONE
log_slave_updates = ON
log_bin = mysql-bin
binlog_format = ROW
master_info_repository = TABLE
relay_log_info_repository = TABLE

# MGR 配置
plugin_load_add = 'group_replication.so'
transaction_write_set_extraction = XXHASH64
group_replication_group_name = "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa"
group_replication_start_on_boot = OFF
group_replication_local_address = "192.168.1.10:33061"
group_replication_group_seeds = "192.168.1.10:33061,192.168.1.11:33061,192.168.1.12:33061"
group_replication_bootstrap_group = OFF
```

**初始化 MGR**：
```sql
-- Node1 执行
SET SQL_LOG_BIN=0;
CREATE USER 'repl'@'%' IDENTIFIED BY 'Repl@123456';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;
SET SQL_LOG_BIN=1;

CHANGE MASTER TO MASTER_USER='repl', MASTER_PASSWORD='Repl@123456' 
FOR CHANNEL 'group_replication_recovery';

SET GLOBAL group_replication_bootstrap_group=ON;
START GROUP_REPLICATION;
SET GLOBAL group_replication_bootstrap_group=OFF;

-- Node2 和 Node3 执行
SET SQL_LOG_BIN=0;
CREATE USER 'repl'@'%' IDENTIFIED BY 'Repl@123456';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;
SET SQL_LOG_BIN=1;

CHANGE MASTER TO MASTER_USER='repl', MASTER_PASSWORD='Repl@123456' 
FOR CHANNEL 'group_replication_recovery';

START GROUP_REPLICATION;
```

**查看集群状态**：
```sql
SELECT * FROM performance_schema.replication_group_members;
```

## 4. ProxySQL 中间件

### 4.1 安装 ProxySQL

```bash
# CentOS/RHEL
yum install -y proxysql

# 启动
systemctl start proxysql
systemctl enable proxysql
```

### 4.2 配置 ProxySQL

```bash
# 登录管理端口
mysql -u admin -padmin -h 127.0.0.1 -P6032

-- 添加后端 MySQL 服务器
INSERT INTO mysql_servers(hostgroup_id, hostname, port, weight)
VALUES 
(1, '192.168.1.10', 3306, 1000),  -- Master
(2, '192.168.1.11', 3306, 1000),  -- Slave1
(2, '192.168.1.12', 3306, 1000);  -- Slave2

LOAD MYSQL SERVERS TO RUNTIME;
SAVE MYSQL SERVERS TO DISK;

-- 添加用户
INSERT INTO mysql_users(username, password, default_hostgroup)
VALUES ('app_user', 'AppPass@123', 1);

LOAD MYSQL USERS TO RUNTIME;
SAVE MYSQL USERS TO DISK;

-- 配置读写分离规则
INSERT INTO mysql_query_rules(rule_id, active, match_pattern, destination_hostgroup, apply)
VALUES 
(1, 1, '^SELECT.*FOR UPDATE$', 1, 1),
(2, 1, '^SELECT', 2, 1);

LOAD MYSQL QUERY RULES TO RUNTIME;
SAVE MYSQL QUERY RULES TO DISK;

-- 配置监控
INSERT INTO mysql_replication_hostgroups(writer_hostgroup, reader_hostgroup)
VALUES (1, 2);

LOAD MYSQL SERVERS TO RUNTIME;
```

### 4.3 应用连接 ProxySQL

```python
import pymysql

# 连接 ProxySQL
conn = pymysql.connect(
    host='127.0.0.1',
    port=6033,
    user='app_user',
    password='AppPass@123',
    database='mydb'
)

cursor = conn.cursor()

# 写操作（路由到 Master）
cursor.execute("INSERT INTO users (username) VALUES ('test')")
conn.commit()

# 读操作（路由到 Slave）
cursor.execute("SELECT * FROM users")
results = cursor.fetchall()

cursor.close()
conn.close()
```

## 5. 故障切换

### 5.1 自动故障切换

**MHA 自动切换流程**：
```
1. Manager 检测到 Master 故障
2. 选择最新的 Slave 作为新 Master
3. 应用差异 Relay Log
4. 提升为新 Master
5. 其他 Slave 指向新 Master
6. 切换 VIP
7. 通知应用程序
```

### 5.2 手动故障切换

```bash
# 1. 停止 MHA Manager
masterha_stop --conf=/etc/mha/app1.cnf

# 2. 手动切换
masterha_master_switch \
    --conf=/etc/mha/app1.cnf \
    --master_state=alive \
    --new_master_host=192.168.1.11 \
    --new_master_port=3306 \
    --orig_master_is_new_slave

# 3. 重启 MHA Manager
nohup masterha_manager --conf=/etc/mha/app1.cnf > /var/log/mha/app1/manager.log 2>&1 &
```

## 6. 数据一致性

### 6.1 半同步复制

```sql
-- 主库安装插件
INSTALL PLUGIN rpl_semi_sync_master SONAME 'semisync_master.so';
SET GLOBAL rpl_semi_sync_master_enabled = 1;
SET GLOBAL rpl_semi_sync_master_timeout = 1000;

-- 从库安装插件
INSTALL PLUGIN rpl_semi_sync_slave SONAME 'semisync_slave.so';
SET GLOBAL rpl_semi_sync_slave_enabled = 1;

-- 重启从库 I/O 线程
STOP SLAVE IO_THREAD;
START SLAVE IO_THREAD;
```

### 6.2 数据校验

```bash
# 使用 pt-table-checksum
pt-table-checksum \
    --host=192.168.1.10 \
    --user=root \
    --password=password \
    --databases=mydb \
    --replicate=percona.checksums

# 修复数据不一致
pt-table-sync \
    --execute \
    --sync-to-master \
    h=192.168.1.11,u=root,p=password
```

## 1. 硬件优化

### 1.1 CPU 优化

**选择建议**：
- 核心数 > 主频（MySQL 支持多核并发）
- 推荐：8核+ 2.4GHz+
- OLTP 场景：更多核心
- OLAP 场景：更高主频

**优化配置**：
```ini
# my.cnf
[mysqld]
# CPU 亲和性（绑定 CPU 核心）
innodb_read_io_threads = 4
innodb_write_io_threads = 4

# 并发连接数
max_connections = 500
```

### 1.2 内存优化

**内存分配原则**：
```
总内存 = InnoDB Buffer Pool + 其他缓冲 + 连接内存 + OS 缓存

推荐配置（16GB 内存服务器）：
- InnoDB Buffer Pool: 10-12GB (70-75%)
- OS 缓存: 2-3GB
- 连接内存: 1-2GB
- 其他: 1-2GB
```

**关键参数**：
```ini
[mysqld]
# InnoDB 缓冲池（最重要）
innodb_buffer_pool_size = 12G
innodb_buffer_pool_instances = 8

# 查询缓存（MySQL 8.0 已移除）
# query_cache_size = 0

# 排序缓冲
sort_buffer_size = 2M
join_buffer_size = 2M

# 读缓冲
read_buffer_size = 1M
read_rnd_buffer_size = 1M

# 临时表
tmp_table_size = 64M
max_heap_table_size = 64M
```

### 1.3 磁盘优化

**磁盘选择**：
```
SSD > RAID 10 > RAID 5 > 单盘

推荐配置：
- 数据文件：SSD（高 IOPS）
- 日志文件：SSD 或 RAID 10
- 备份文件：普通硬盘
```

**文件系统**：
```bash
# 推荐使用 XFS 或 ext4
mkfs.xfs /dev/sdb1

# 挂载选项
mount -o noatime,nodiratime /dev/sdb1 /data/mysql
```

**I/O 调度器**：
```bash
# 查看当前调度器
cat /sys/block/sda/queue/scheduler

# 设置为 deadline（推荐 SSD）
echo deadline > /sys/block/sda/queue/scheduler

# 设置为 noop（推荐 SSD）
echo noop > /sys/block/sda/queue/scheduler
```

### 1.4 网络优化

```bash
# 增大 TCP 缓冲区
sysctl -w net.core.rmem_max=16777216
sysctl -w net.core.wmem_max=16777216
sysctl -w net.ipv4.tcp_rmem="4096 87380 16777216"
sysctl -w net.ipv4.tcp_wmem="4096 65536 16777216"

# 增大连接队列
sysctl -w net.core.somaxconn=2048
sysctl -w net.ipv4.tcp_max_syn_backlog=2048
```

## 2. 参数优化

### 2.1 连接相关

```ini
[mysqld]
# 最大连接数
max_connections = 500

# 连接超时
wait_timeout = 28800
interactive_timeout = 28800

# 连接错误次数
max_connect_errors = 100

# 线程缓存
thread_cache_size = 100

# 打开文件数
open_files_limit = 65535
table_open_cache = 4000
```

**计算公式**：
```
max_connections = (可用内存 - InnoDB Buffer Pool) / 单连接内存
单连接内存 ≈ sort_buffer_size + read_buffer_size + join_buffer_size + 其他
```

### 2.2 InnoDB 优化

```ini
[mysqld]
# 缓冲池
innodb_buffer_pool_size = 12G
innodb_buffer_pool_instances = 8

# 日志文件
innodb_log_file_size = 1G
innodb_log_files_in_group = 2
innodb_log_buffer_size = 32M

# 刷新策略
innodb_flush_log_at_trx_commit = 1  # 1=最安全，2=性能好
innodb_flush_method = O_DIRECT       # 避免双重缓冲

# I/O 线程
innodb_read_io_threads = 8
innodb_write_io_threads = 8

# 页大小
innodb_page_size = 16K

# 自适应哈希索引
innodb_adaptive_hash_index = ON

# 文件格式
innodb_file_format = Barracuda
innodb_file_per_table = ON

# 锁等待超时
innodb_lock_wait_timeout = 50

# 并发线程数
innodb_thread_concurrency = 0  # 0=自动
```

### 2.3 查询优化参数

```ini
[mysqld]
# 慢查询日志
slow_query_log = ON
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 1
log_queries_not_using_indexes = ON

# 查询缓存（MySQL 8.0 已移除）
# query_cache_type = 0
# query_cache_size = 0

# 排序和分组
max_sort_length = 1024
group_concat_max_len = 1024

# 临时表
tmp_table_size = 64M
max_heap_table_size = 64M
```

### 2.4 Binlog 优化

```ini
[mysqld]
# Binlog 配置
log_bin = mysql-bin
binlog_format = ROW
binlog_cache_size = 4M
max_binlog_size = 1G
expire_logs_days = 7

# 同步策略
sync_binlog = 1  # 1=最安全，0=性能好

# 行镜像
binlog_row_image = MINIMAL  # 减少 Binlog 大小
```

## 3. SQL 优化

### 3.1 索引优化

**创建合适的索引**：
```sql
-- ❌ 没有索引
SELECT * FROM users WHERE email = 'user@example.com';

-- ✅ 创建索引
CREATE INDEX idx_email ON users(email);

-- ✅ 联合索引（遵循最左前缀）
CREATE INDEX idx_name_age ON users(name, age);

-- ✅ 覆盖索引（避免回表）
CREATE INDEX idx_name_email ON users(name, email);
SELECT name, email FROM users WHERE name = '张三';
```

**避免索引失效**：
```sql
-- ❌ 使用函数
SELECT * FROM users WHERE YEAR(created_at) = 2024;

-- ✅ 使用范围
SELECT * FROM users 
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31';

-- ❌ 隐式类型转换
SELECT * FROM users WHERE phone = 13800138000;  -- phone 是 VARCHAR

-- ✅ 使用正确类型
SELECT * FROM users WHERE phone = '13800138000';

-- ❌ 前导模糊查询
SELECT * FROM users WHERE email LIKE '%@gmail.com';

-- ✅ 后缀模糊查询
SELECT * FROM users WHERE email LIKE 'user%';
```

### 3.2 查询优化

**避免 SELECT ***：
```sql
-- ❌ 查询所有字段
SELECT * FROM users WHERE id = 1;

-- ✅ 只查询需要的字段
SELECT id, username, email FROM users WHERE id = 1;
```

**优化 JOIN**：
```sql
-- ❌ 笛卡尔积
SELECT * FROM users, orders;

-- ✅ 使用 JOIN
SELECT u.username, o.order_no
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- ✅ 小表驱动大表
SELECT u.username, o.order_no
FROM orders o  -- 小表
INNER JOIN users u ON o.user_id = u.id;  -- 大表
```

**优化子查询**：
```sql
-- ❌ 子查询
SELECT * FROM users
WHERE id IN (SELECT user_id FROM orders WHERE amount > 1000);

-- ✅ 使用 JOIN
SELECT DISTINCT u.*
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE o.amount > 1000;
```

**优化分页**：
```sql
-- ❌ 深分页
SELECT * FROM users ORDER BY id LIMIT 100000, 10;

-- ✅ 使用子查询
SELECT * FROM users
WHERE id >= (SELECT id FROM users ORDER BY id LIMIT 100000, 1)
ORDER BY id LIMIT 10;

-- ✅ 记录上次位置
SELECT * FROM users WHERE id > 100000 ORDER BY id LIMIT 10;
```

### 3.3 批量操作优化

```sql
-- ❌ 逐条插入
INSERT INTO users (username) VALUES ('user1');
INSERT INTO users (username) VALUES ('user2');
INSERT INTO users (username) VALUES ('user3');

-- ✅ 批量插入
INSERT INTO users (username) VALUES 
('user1'), ('user2'), ('user3');

-- ❌ 逐条更新
UPDATE users SET status = 1 WHERE id = 1;
UPDATE users SET status = 1 WHERE id = 2;
UPDATE users SET status = 1 WHERE id = 3;

-- ✅ 批量更新
UPDATE users SET status = 1 WHERE id IN (1, 2, 3);
```

## 4. 表结构优化

### 4.1 字段类型优化

```sql
-- ✅ 使用合适的数据类型
CREATE TABLE optimized_table (
    -- 整数类型
    id INT UNSIGNED PRIMARY KEY AUTO_INCREMENT,  -- 使用 UNSIGNED
    age TINYINT UNSIGNED,  -- 0-255，够用就行
    
    -- 字符串类型
    username VARCHAR(50) NOT NULL,  -- 固定长度用 VARCHAR
    mobile CHAR(11),  -- 固定长度用 CHAR
    
    -- 枚举类型
    gender ENUM('M', 'F', 'U') DEFAULT 'U',
    
    -- 日期类型
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- 金额类型
    amount DECIMAL(10,2),  -- 精确计算用 DECIMAL
    
    -- 索引
    INDEX idx_username (username),
    INDEX idx_mobile (mobile)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 表拆分

**垂直拆分**：
```sql
-- 原表（字段太多）
CREATE TABLE users_all (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100),
    password VARCHAR(255),
    profile TEXT,  -- 大字段
    settings JSON,  -- 大字段
    created_at DATETIME
);

-- 拆分后
-- 主表（常用字段）
CREATE TABLE users (
    id INT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100),
    password VARCHAR(255),
    created_at DATETIME
);

-- 扩展表（不常用字段）
CREATE TABLE user_profiles (
    user_id INT PRIMARY KEY,
    profile TEXT,
    settings JSON,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**水平拆分**：
```sql
-- 按时间拆分
CREATE TABLE orders_2023 (
    id INT PRIMARY KEY,
    user_id INT,
    amount DECIMAL(10,2),
    created_at DATETIME
);

CREATE TABLE orders_2024 (
    id INT PRIMARY KEY,
    user_id INT,
    amount DECIMAL(10,2),
    created_at DATETIME
);

-- 按范围拆分
CREATE TABLE users_0 (  -- id % 4 = 0
    id INT PRIMARY KEY,
    username VARCHAR(50)
);

CREATE TABLE users_1 (  -- id % 4 = 1
    id INT PRIMARY KEY,
    username VARCHAR(50)
);
```

## 5. 分区表

### 5.1 分区类型

**RANGE 分区（按范围）**：
```sql
CREATE TABLE orders_range (
    id INT,
    user_id INT,
    amount DECIMAL(10,2),
    created_at DATE
)
PARTITION BY RANGE (YEAR(created_at)) (
    PARTITION p2022 VALUES LESS THAN (2023),
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION p_future VALUES LESS THAN MAXVALUE
);
```

**LIST 分区（按列表）**：
```sql
CREATE TABLE users_list (
    id INT,
    username VARCHAR(50),
    city VARCHAR(50)
)
PARTITION BY LIST COLUMNS(city) (
    PARTITION p_north VALUES IN ('北京', '天津', '河北'),
    PARTITION p_east VALUES IN ('上海', '江苏', '浙江'),
    PARTITION p_south VALUES IN ('广东', '深圳', '福建')
);
```

**HASH 分区（按哈希）**：
```sql
CREATE TABLE users_hash (
    id INT,
    username VARCHAR(50)
)
PARTITION BY HASH(id)
PARTITIONS 4;
```

**KEY 分区**：
```sql
CREATE TABLE users_key (
    id INT,
    username VARCHAR(50)
)
PARTITION BY KEY(id)
PARTITIONS 4;
```

### 5.2 分区管理

```sql
-- 查看分区信息
SELECT 
    TABLE_NAME,
    PARTITION_NAME,
    PARTITION_METHOD,
    PARTITION_EXPRESSION,
    TABLE_ROWS
FROM information_schema.PARTITIONS
WHERE TABLE_NAME = 'orders_range';

-- 添加分区
ALTER TABLE orders_range 
ADD PARTITION (PARTITION p2025 VALUES LESS THAN (2026));

-- 删除分区
ALTER TABLE orders_range DROP PARTITION p2022;

-- 重组分区
ALTER TABLE orders_range 
REORGANIZE PARTITION p_future INTO (
    PARTITION p2025 VALUES LESS THAN (2026),
    PARTITION p_future VALUES LESS THAN MAXVALUE
);

-- 查询指定分区
SELECT * FROM orders_range PARTITION (p2024);
```

### 5.3 分区优化

```sql
-- ✅ 分区裁剪（Partition Pruning）
EXPLAIN SELECT * FROM orders_range 
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31';
-- 只扫描 p2024 分区

-- ✅ 分区索引
CREATE INDEX idx_user_id ON orders_range(user_id);
-- 每个分区都有独立的索引

-- ⚠️ 注意事项
-- 1. 分区字段必须是主键或唯一索引的一部分
-- 2. 分区数量不宜过多（建议 < 1000）
-- 3. 查询条件要包含分区字段
```

## 7. 实战案例

### 案例1：优化慢查询

```sql
-- 1. 发现慢查询
SELECT * FROM orders 
WHERE user_id = 1000 
  AND status = 'completed'
  AND created_at >= '2024-01-01'
ORDER BY created_at DESC
LIMIT 10;

-- 2. 分析执行计划
EXPLAIN SELECT * FROM orders 
WHERE user_id = 1000 
  AND status = 'completed'
  AND created_at >= '2024-01-01'
ORDER BY created_at DESC
LIMIT 10;
-- type: ALL（全表扫描）
-- rows: 1000000

-- 3. 创建索引
CREATE INDEX idx_user_status_time 
ON orders(user_id, status, created_at);

-- 4. 再次分析
EXPLAIN SELECT * FROM orders 
WHERE user_id = 1000 
  AND status = 'completed'
  AND created_at >= '2024-01-01'
ORDER BY created_at DESC
LIMIT 10;
-- type: range
-- rows: 100

-- 5. 性能对比
-- 优化前：2.5 秒
-- 优化后：0.01 秒
```

### 案例2：参数调优

```bash
# 1. 查看当前配置
mysql -u root -p -e "SHOW VARIABLES" > current_config.txt

# 2. 分析瓶颈
# - Buffer Pool 命中率低
# - 连接数不足
# - 日志刷新频繁

# 3. 优化配置
cat > /etc/my.cnf << EOF
[mysqld]
# 增大缓冲池
innodb_buffer_pool_size = 12G
innodb_buffer_pool_instances = 8

# 增大连接数
max_connections = 1000
thread_cache_size = 200

# 优化日志
innodb_log_file_size = 2G
innodb_flush_log_at_trx_commit = 2

# 优化 I/O
innodb_read_io_threads = 8
innodb_write_io_threads = 8
innodb_flush_method = O_DIRECT
EOF

# 4. 重启 MySQL
systemctl restart mysqld

# 5. 验证效果
# - QPS 提升 50%
# - 响应时间降低 30%
```

# 健康检查与故障转移

## 什么是健康检查？

**健康检查（Health Check）** 是 Keepalived 监控服务状态的机制，当检测到服务故障时，自动触发故障转移。

### 为什么需要健康检查？

默认情况下，Keepalived 只检测服务器是否存活，不检测服务是否正常。即使服务已经停止，只要服务器还在运行，VIP 就不会切换。

**问题场景**：
- Nginx 服务停止，但服务器正常 → VIP 不切换 → 服务不可用
- MySQL 服务故障，但服务器正常 → VIP 不切换 → 数据库不可用

**解决方案**：配置健康检查脚本，监控服务状态。

## vrrp_script 配置

### 基本语法

```bash
vrrp_script <脚本名称> {
    script "<检查脚本>"      # 检查脚本路径或命令
    interval <秒>            # 检查间隔（秒）
    weight <权重>            # 权重调整
    fall <次数>              # 失败次数阈值
    rise <次数>              # 成功次数阈值
}
```

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `script` | 检查脚本或命令 | 必填 |
| `interval` | 检查间隔（秒） | 1 |
| `weight` | 权重调整（正数或负数） | 0 |
| `fall` | 连续失败多少次判定为失败 | 1 |
| `rise` | 连续成功多少次判定为成功 | 1 |

### weight 权重说明

- **正数**：脚本成功时增加优先级
- **负数**：脚本失败时降低优先级（推荐）

**示例**：
```bash
priority 100
weight -20

# 服务正常：优先级 = 100
# 服务故障：优先级 = 100 - 20 = 80（低于备服务器，触发切换）
```

## 健康检查脚本

### 1. 检查进程是否存在

```bash
#!/bin/bash
# /etc/keepalived/check_nginx.sh

# 检查 Nginx 进程
if [ $(ps -C nginx --no-header | wc -l) -eq 0 ]; then
    exit 1  # 进程不存在，返回失败
else
    exit 0  # 进程存在，返回成功
fi
```

### 2. 检查端口是否监听

```bash
#!/bin/bash
# /etc/keepalived/check_port.sh

# 检查 80 端口是否监听
if netstat -tunlp | grep -q ":80 "; then
    exit 0  # 端口监听，返回成功
else
    exit 1  # 端口未监听，返回失败
fi
```

### 3. 检查 HTTP 响应

```bash
#!/bin/bash
# /etc/keepalived/check_http.sh

# 检查 HTTP 响应
curl -s -o /dev/null -w "%{http_code}" http://localhost | grep -q "200"
if [ $? -eq 0 ]; then
    exit 0  # HTTP 200，返回成功
else
    exit 1  # 非 200，返回失败
fi
```

### 4. 检查 MySQL 服务

```bash
#!/bin/bash
# /etc/keepalived/check_mysql.sh

# MySQL 连接信息
MYSQL_HOST="localhost"
MYSQL_USER="root"
MYSQL_PASS="password"

# 检查 MySQL 连接
mysql -h$MYSQL_HOST -u$MYSQL_USER -p$MYSQL_PASS -e "SELECT 1" &>/dev/null
if [ $? -eq 0 ]; then
    exit 0  # 连接成功
else
    exit 1  # 连接失败
fi
```

### 5. 综合检查脚本

```bash
#!/bin/bash
# /etc/keepalived/check_nginx_advanced.sh

# 检查 Nginx 进程
if [ $(ps -C nginx --no-header | wc -l) -eq 0 ]; then
    # 尝试启动 Nginx
    systemctl start nginx
    sleep 2
    
    # 再次检查
    if [ $(ps -C nginx --no-header | wc -l) -eq 0 ]; then
        exit 1  # 启动失败
    fi
fi

# 检查 HTTP 响应
curl -s -o /dev/null -w "%{http_code}" http://localhost | grep -q "200"
if [ $? -eq 0 ]; then
    exit 0  # 检查成功
else
    exit 1  # 检查失败
fi
```

## 完整配置示例

### Nginx 高可用配置

#### MASTER 配置

```bash
# /etc/keepalived/keepalived.conf (主服务器)

global_defs {
    router_id NGINX_MASTER
}

# 定义健康检查脚本
vrrp_script check_nginx {
    script "/etc/keepalived/check_nginx.sh"
    interval 2          # 每 2 秒检查一次
    weight -20          # 失败时降低优先级 20
    fall 3              # 连续失败 3 次判定为失败
    rise 2              # 连续成功 2 次判定为成功
}

vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1
    
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    
    virtual_ipaddress {
        192.168.1.100
    }
    
    # 引用健康检查脚本
    track_script {
        check_nginx
    }
}
```

#### BACKUP 配置

```bash
# /etc/keepalived/keepalived.conf (备服务器)

global_defs {
    router_id NGINX_BACKUP
}

    weight -20
    fall 3
    rise 2
}

vrrp_instance VI_1 {
    state BACKUP
    interface eth0
    virtual_router_id 51
    priority 90
    advert_int 1
    
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    
    virtual_ipaddress {
        192.168.1.100
    }
    
    # 引用健康检查脚本
    track_script {
        check_nginx
    }
}
```

#### 健康检查脚本

```bash
# /etc/keepalived/check_nginx.sh

#!/bin/bash

# 检查 Nginx 进程
if [ $(ps -C nginx --no-header | wc -l) -eq 0 ]; then
    exit 1
fi

# 检查 HTTP 响应
curl -s -o /dev/null -w "%{http_code}" http://localhost | grep -q "200"
if [ $? -eq 0 ]; then
    exit 0
else
    exit 1
fi
```

```bash
# 设置脚本权限
chmod +x /etc/keepalived/check_nginx.sh

# 重启 Keepalived
systemctl restart keepalived
```

## 故障转移场景

### 场景 1：服务器宕机

```
初始状态：
  MASTER (192.168.1.10) - 拥有 VIP
  BACKUP (192.168.1.11) - 待命

故障发生：
  MASTER 服务器宕机

故障转移：
  1. BACKUP 检测不到 MASTER 的 VRRP 通告
  2. 等待 3 个通告间隔（3 秒）
  3. BACKUP 切换为 MASTER
  4. BACKUP 绑定 VIP
  5. 发送免费 ARP，更新网络设备的 ARP 缓存

结果：
  BACKUP (192.168.1.11) - 拥有 VIP
  服务恢复
```

### 场景 2：服务故障

```
初始状态：
  MASTER (192.168.1.10) - 拥有 VIP，Nginx 运行
  BACKUP (192.168.1.11) - 待命，Nginx 运行

故障发生：
  MASTER 的 Nginx 服务停止

故障转移：
  1. 健康检查脚本检测到 Nginx 停止
  2. 连续失败 3 次（6 秒）
  3. MASTER 优先级降低：100 - 20 = 80
  4. BACKUP 优先级（90）高于 MASTER（80）
  5. BACKUP 切换为 MASTER
  6. BACKUP 绑定 VIP

结果：
  BACKUP (192.168.1.11) - 拥有 VIP
  服务恢复
```

### 场景 3：服务恢复

```
初始状态：
  原 MASTER (192.168.1.10) - 无 VIP，Nginx 停止
  原 BACKUP (192.168.1.11) - 拥有 VIP，Nginx 运行

恢复操作：
  启动原 MASTER 的 Nginx 服务

故障恢复：
  1. 健康检查脚本检测到 Nginx 启动
  2. 连续成功 2 次（4 秒）
  3. 原 MASTER 优先级恢复：80 + 20 = 100
  4. 原 MASTER 优先级（100）高于当前 MASTER（90）
  5. 原 MASTER 重新成为 MASTER
  6. 原 MASTER 绑定 VIP

结果：
  原 MASTER (192.168.1.10) - 拥有 VIP
  VIP 回到原 MASTER
```

## 非抢占模式

### 什么是非抢占模式？

**非抢占模式（nopreempt）**：即使原 MASTER 恢复，也不会抢回 VIP，除非当前 MASTER 故障。

### 为什么使用非抢占模式？

- **减少切换次数**：避免频繁切换导致服务中断
- **稳定性优先**：当前 MASTER 运行正常，无需切换
- **适合数据库**：减少主从切换，避免数据不一致

### 配置非抢占模式

```bash
vrrp_instance VI_1 {
    state BACKUP        # 主备都设置为 BACKUP
    interface eth0
    virtual_router_id 51
    priority 100        # 通过优先级区分主备
    advert_int 1
    nopreempt           # 开启非抢占模式（只在高优先级节点配置）
    
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    
    virtual_ipaddress {
        192.168.1.100
    }
}
```

**注意**：
- 主备都设置为 `state BACKUP`
- 只在高优先级节点配置 `nopreempt`
- 通过 `priority` 区分主备

## 通知脚本

### notify 脚本

当 Keepalived 状态变化时，执行通知脚本。

```bash
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1
    
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    
    virtual_ipaddress {
        192.168.1.100
    }
    
    # 通知脚本
    notify_master "/etc/keepalived/notify_master.sh"
    notify_backup "/etc/keepalived/notify_backup.sh"
    notify_fault "/etc/keepalived/notify_fault.sh"
}
```

### 通知脚本示例

#### notify_master.sh（切换为 MASTER）

```bash
#!/bin/bash
# /etc/keepalived/notify_master.sh

LOG_FILE="/var/log/keepalived_notify.log"
echo "$(date) - 切换为 MASTER" >> $LOG_FILE

# 发送邮件通知
echo "Keepalived 切换为 MASTER" | mail -s "Keepalived Alert" admin@example.com

# 发送钉钉通知（可选）
# curl -X POST "https://oapi.dingtalk.com/robot/send?access_token=xxx" \
#   -H 'Content-Type: application/json' \
#   -d '{"msgtype":"text","text":{"content":"Keepalived 切换为 MASTER"}}'
```

#### notify_backup.sh（切换为 BACKUP）

```bash
#!/bin/bash
# /etc/keepalived/notify_backup.sh

LOG_FILE="/var/log/keepalived_notify.log"
echo "$(date) - 切换为 BACKUP" >> $LOG_FILE

# 发送邮件通知
echo "Keepalived 切换为 BACKUP" | mail -s "Keepalived Alert" admin@example.com
```

#### notify_fault.sh（进入故障状态）

```bash
#!/bin/bash
# /etc/keepalived/notify_fault.sh

LOG_FILE="/var/log/keepalived_notify.log"
echo "$(date) - 进入故障状态" >> $LOG_FILE

# 发送紧急通知
echo "Keepalived 进入故障状态！" | mail -s "Keepalived FAULT" admin@example.com
```

```bash
# 设置脚本权限
chmod +x /etc/keepalived/notify_*.sh
```

```bash
global_defs {
```

## 监控和调试

### 查看 Keepalived 状态

```bash
# 查看服务状态
systemctl status keepalived

# 查看日志
tail -f /var/log/messages | grep Keepalived

# 查看 VIP
ip addr show eth0 | grep 192.168.1.100

# 查看 VRRP 通告
tcpdump -i eth0 vrrp
```

### 调试健康检查脚本

```bash
# 手动执行脚本
/etc/keepalived/check_nginx.sh
echo $?  # 0 表示成功，非 0 表示失败

# 查看脚本日志
tail -f /var/log/messages | grep vrrp_script
```

### 常见问题排查

```bash
# 1. 检查配置文件语法
keepalived -t -f /etc/keepalived/keepalived.conf

# 2. 检查脚本权限
ls -l /etc/keepalived/check_nginx.sh

# 3. 检查脚本是否可执行
bash -x /etc/keepalived/check_nginx.sh

# 4. 查看优先级变化
```

# 系统定时任务

## 系统级 vs 用户级

| 类型 | 配置文件 | 权限 | 用途 |
|------|---------|------|------|
| 用户级 | `crontab -e` | 普通用户 | 个人任务 |
| 系统级 | `/etc/crontab` | root | 系统任务 |
| 系统级 | `/etc/cron.d/` | root | 软件包任务 |

---

## 一、/etc/crontab

### 文件格式

```bash
cat /etc/crontab
```

```
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root

# 分 时 日 月 周 用户 命令
# m  h  dom mon dow user command

# 每小时执行
01 * * * * root run-parts /etc/cron.hourly

# 每天执行
02 4 * * * root run-parts /etc/cron.daily

# 每周执行
22 4 * * 0 root run-parts /etc/cron.weekly

# 每月执行
42 4 1 * * root run-parts /etc/cron.monthly
```

### 与用户 crontab 的区别

```bash
# 用户 crontab（5个字段）
分 时 日 月 周 命令

# 系统 crontab（6个字段，多了用户）
分 时 日 月 周 用户 命令
```

### 添加系统任务

```bash
# 编辑 /etc/crontab
vim /etc/crontab

# 添加任务（注意要指定用户）
0 2 * * * root /scripts/system_backup.sh
30 3 * * * www-data /scripts/clean_cache.sh
```

## 二、/etc/cron.d/

### 目录说明

```bash
ls -l /etc/cron.d/
# 每个文件都是一个独立的 crontab 配置
```

### 创建系统任务

```bash
# 创建任务文件
cat > /etc/cron.d/myapp << 'EOF'
# 每5分钟检查应用状态
*/5 * * * * root /scripts/check_myapp.sh >> /var/log/myapp_check.log 2>&1

# 每天凌晨2点备份
0 2 * * * root /scripts/backup_myapp.sh >> /var/log/myapp_backup.log 2>&1
EOF

# 设置权限
chmod 644 /etc/cron.d/myapp
```

### 文件命名规则

```bash
# ✅ 正确的文件名
/etc/cron.d/myapp
/etc/cron.d/backup-task
/etc/cron.d/monitor_service

# ❌ 错误的文件名（会被忽略）
/etc/cron.d/myapp.sh          # 不能有 .sh 后缀
/etc/cron.d/backup.bak        # 不能有 .bak 后缀
/etc/cron.d/test~             # 不能有 ~ 后缀
```

## 三、/etc/cron.{hourly,daily,weekly,monthly}

### 目录结构

```bash
/etc/cron.hourly/             # 每小时执行的脚本
/etc/cron.daily/              # 每天执行的脚本
/etc/cron.weekly/             # 每周执行的脚本
/etc/cron.monthly/            # 每月执行的脚本
```

### 添加脚本

```bash
# 创建每日备份脚本
cat > /etc/cron.daily/backup << 'EOF'
#!/bin/bash
/usr/bin/mysqldump -u root -ppassword mydb > /backup/mydb_$(date +%Y%m%d).sql
find /backup -name "mydb_*.sql" -mtime +7 -delete
EOF

# 设置权限（必须可执行）
chmod +x /etc/cron.daily/backup

# 脚本会在每天凌晨自动执行
```

### 执行时间

```bash
# 查看 /etc/crontab 或 /etc/anacrontab
cat /etc/crontab

# 默认执行时间（可能因发行版而异）
# hourly:  每小时的第1分钟
# daily:   每天凌晨4:02
# weekly:  每周日凌晨4:22
# monthly: 每月1日凌晨4:42
```

### 脚本要求

```bash
# 1. 必须有执行权限
chmod +x /etc/cron.daily/myscript

# 2. 必须有 shebang
#!/bin/bash

# 3. 文件名不能有扩展名
# ✅ 正确
/etc/cron.daily/backup
/etc/cron.daily/cleanup

# ❌ 错误（会被忽略）
/etc/cron.daily/backup.sh
/etc/cron.daily/cleanup.bak
```

## 四、anacron

### 什么是 anacron

anacron 用于执行周期性任务，即使系统在预定时间关机也能补执行。

```
cron:    精确到分钟，系统关机任务不执行
anacron: 按天/周/月，系统开机后补执行错过的任务
```

### 配置文件

```bash
cat /etc/anacrontab
```

```
# 周期(天) 延迟(分钟) 任务标识 命令
# period   delay      job-id   command

1         5          cron.daily    run-parts /etc/cron.daily
7         10         cron.weekly   run-parts /etc/cron.weekly
@monthly  15         cron.monthly  run-parts /etc/cron.monthly
```

### 字段说明

| 字段 | 说明 |
|------|------|
| period | 执行周期（天），或 @daily/@weekly/@monthly |
| delay | 系统启动后延迟多少分钟执行 |
| job-id | 任务标识符 |
| command | 要执行的命令 |

### anacron 工作流程

```
1. 系统启动
2. anacron 检查 /var/spool/anacron/ 中的时间戳
3. 如果任务超期未执行，等待 delay 分钟后执行
4. 执行完成后更新时间戳
```

### 手动运行 anacron

```bash
# 立即执行所有任务
anacron -f

# 执行特定任务
anacron -f -t /etc/anacrontab cron.daily

# 测试模式（不实际执行）
anacron -d -n
```

## 五、实战案例

### 案例1：系统日志清理

```bash
# 创建脚本
cat > /etc/cron.daily/clean-logs << 'EOF'
#!/bin/bash

# 清理系统日志
find /var/log -name "*.log" -mtime +30 -delete
find /var/log -name "*.gz" -mtime +90 -delete

# 清理应用日志
find /var/log/nginx -name "*.log" -mtime +7 -delete
find /var/log/mysql -name "*.log" -mtime +7 -delete

# 记录清理时间
echo "$(date): Log cleanup completed" >> /var/log/cleanup.log
EOF

chmod +x /etc/cron.daily/clean-logs
```

### 案例2：系统更新检查

```bash
# 创建脚本
cat > /etc/cron.weekly/check-updates << 'EOF'
#!/bin/bash

# 检查可用更新
yum check-update > /tmp/updates.txt 2>&1

# 如果有更新，发送邮件
if [ -s /tmp/updates.txt ]; then
    mail -s "System Updates Available" admin@example.com < /tmp/updates.txt
fi
EOF

chmod +x /etc/cron.weekly/check-updates
```

### 案例3：数据库维护

```bash
# 创建配置文件
cat > /etc/cron.d/mysql-maintenance << 'EOF'
# 每天凌晨2点优化数据库
0 2 * * * root /usr/bin/mysqlcheck -u root -ppassword --optimize --all-databases >> /var/log/mysql_optimize.log 2>&1

# 每周日凌晨3点修复数据库
0 3 * * 0 root /usr/bin/mysqlcheck -u root -ppassword --repair --all-databases >> /var/log/mysql_repair.log 2>&1
EOF

chmod 644 /etc/cron.d/mysql-maintenance
```

### 案例4：监控磁盘空间

```bash
# 创建脚本
cat > /etc/cron.hourly/disk-monitor << 'EOF'
#!/bin/bash

THRESHOLD=80
ALERT_EMAIL="admin@example.com"

# 检查所有挂载点
df -h | awk 'NR>1 {print $5,$6}' | while read usage mount; do
    usage_num=${usage%\%}
    if [ $usage_num -gt $THRESHOLD ]; then
        echo "Warning: $mount is ${usage} full" | \
            mail -s "Disk Space Alert: $mount" $ALERT_EMAIL
    fi
done
EOF

chmod +x /etc/cron.hourly/disk-monitor
```

## 六、管理系统任务

### 查看所有定时任务

```bash
# 查看用户 crontab
for user in $(cut -d: -f1 /etc/passwd); do
    echo "=== $user ==="
    crontab -u $user -l 2>/dev/null
done

# 查看系统 crontab
cat /etc/crontab

# 查看 cron.d
ls -la /etc/cron.d/
cat /etc/cron.d/*

# 查看定期脚本
ls -la /etc/cron.{hourly,daily,weekly,monthly}/
```

### 禁用系统任务

```bash
# 方法1：注释掉任务
vim /etc/cron.d/myapp
# 在行首添加 #

# 方法2：删除文件
rm /etc/cron.d/myapp

# 方法3：移除执行权限
chmod -x /etc/cron.daily/backup
```

### 测试系统任务

```bash
# 手动执行脚本
/etc/cron.daily/backup

# 使用 run-parts 测试
run-parts --test /etc/cron.daily

# 实际执行
run-parts /etc/cron.daily
```

## 七、最佳实践

### 1. 任务分类

```bash
# 用户任务 → crontab -e
# 系统任务 → /etc/crontab
# 软件包任务 → /etc/cron.d/
# 简单定期任务 → /etc/cron.{daily,weekly,monthly}/
```

### 2. 日志记录

```bash
# 所有系统任务都应该记录日志
0 2 * * * root /scripts/backup.sh >> /var/log/backup.log 2>&1
```

### 3. 错误处理

```bash
#!/bin/bash

# 设置错误时退出
set -e

# 记录开始时间
echo "$(date): Task started" >> /var/log/task.log

# 执行任务
if /scripts/backup.sh; then
    echo "$(date): Task completed successfully" >> /var/log/task.log
else
    echo "$(date): Task failed" >> /var/log/task.log
    exit 1
fi
```

### 4. 权限管理

```bash
# 系统任务文件权限
chmod 644 /etc/cron.d/myapp
chmod 644 /etc/crontab

# 脚本权限
chmod 755 /etc/cron.daily/backup
```

## 练习题

1. 用户 crontab 和系统 crontab 的主要区别是什么？
2. /etc/cron.daily/ 中的脚本什么时候执行？
3. anacron 和 cron 有什么区别？

<details>
<summary>答案</summary>

1. 系统 crontab 需要指定执行用户（6个字段），用户 crontab 不需要（5个字段）
2. 默认每天凌晨4:02执行（具体时间在 /etc/crontab 中配置）
3. cron 精确到分钟，系统关机任务不执行；anacron 按天/周/月，系统开机后会补执行错过的任务

</details>

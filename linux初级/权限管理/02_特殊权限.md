# 特殊权限

除了基本的 rwx 权限，Linux 还有三种特殊权限：SUID、SGID、Sticky Bit。

---

## 一、SUID（Set UID）

### 概念

SUID 作用于可执行文件，让执行者临时拥有文件所有者的权限。

```bash
ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 27856 Jan 7 10:00 /usr/bin/passwd
   ^
   └── s 表示 SUID
```

### 工作原理

```
普通用户执行 passwd 命令
    │
    ▼
临时获得 root 权限
    │
    ▼
可以修改 /etc/shadow（只有 root 可写）
    │
    ▼
命令执行完毕，权限恢复
```

### 设置 SUID

```bash
# 数字方式（4 代表 SUID）
chmod 4755 file                   # rwsr-xr-x
chmod u+s file                    # 符号方式

# 取消 SUID
chmod u-s file
chmod 0755 file
```

### SUID 的显示

| 原权限 | 设置 SUID 后 | 说明 |
|--------|-------------|------|
| rwx | rws | 有 x 权限，显示 s |
| rw- | rwS | 无 x 权限，显示 S（无效） |

### 常见 SUID 文件

```bash
ls -l /usr/bin/passwd             # 修改密码
ls -l /usr/bin/sudo               # sudo 命令
ls -l /usr/bin/ping               # ping 命令（需要 root 权限发送 ICMP）
```

### 安全风险

```bash
# ⚠️ 危险示例（千万别这么做！）
chmod u+s /bin/bash               # 任何人都能获得 root shell
chmod u+s /bin/vim                # 任何人都能以 root 身份编辑文件

# 查找系统中所有 SUID 文件
find / -perm -4000 -type f 2>/dev/null
```

## 二、SGID（Set GID）

### 对文件的作用

SGID 作用于可执行文件，让执行者临时拥有文件所属组的权限。

```bash
chmod 2755 file                   # rwxr-sr-x
chmod g+s file
```

### 对目录的作用（更常用！）

SGID 作用于目录，在该目录中创建的文件自动继承目录的所属组。

```bash
# 创建共享目录
mkdir /data/shared
chgrp developers /data/shared
chmod 2775 /data/shared           # rwxrwsr-x
                                  #      ^
                                  #      └── s 表示 SGID

# 测试
su - user1
cd /data/shared
touch file1.txt
ls -l file1.txt
# -rw-r--r-- 1 user1 developers 0 Jan 7 10:00 file1.txt
#                    │
#                    └── 自动继承 developers 组
```

### 设置 SGID

```bash
# 数字方式（2 代表 SGID）
chmod 2755 directory              # rwxr-sr-x
chmod g+s directory               # 符号方式

# 取消 SGID
chmod g-s directory
chmod 0755 directory
```

### SGID 的显示

| 原权限 | 设置 SGID 后 | 说明 |
|--------|-------------|------|
| r-x | r-s | 有 x 权限，显示 s |
| r-- | r-S | 无 x 权限，显示 S（无效） |

### 实战应用

```bash
# 场景：多人协作项目目录
mkdir /project/alpha
groupadd project_team
chgrp project_team /project/alpha
chmod 2775 /project/alpha

# 添加成员
gpasswd -a user1 project_team
gpasswd -a user2 project_team

# 现在所有成员创建的文件都属于 project_team 组
```

## 三、Sticky Bit（粘滞位）

### 概念

Sticky Bit 作用于目录，只有文件所有者和 root 可以删除该目录中的文件。

```bash
ls -ld /tmp
drwxrwxrwt 10 root root 4096 Jan 7 10:00 /tmp
        ^
        └── t 表示 Sticky Bit
```

### 工作原理

```
/tmp 目录权限是 777（所有人可写）
    │
    ▼
但设置了 Sticky Bit
    │
    ▼
user1 创建的文件，只有 user1 和 root 可以删除
    │
    ▼
user2 无法删除 user1 的文件（即使有 w 权限）
```

### 设置 Sticky Bit

```bash
# 数字方式（1 代表 Sticky Bit）
chmod 1777 directory              # rwxrwxrwt
chmod o+t directory               # 符号方式

# 取消 Sticky Bit
chmod o-t directory
chmod 0777 directory
```

### Sticky Bit 的显示

| 原权限 | 设置 Sticky Bit 后 | 说明 |
|--------|-------------------|------|
| rwx | rwt | 有 x 权限，显示 t |
| rw- | rwT | 无 x 权限，显示 T（无效） |

### 实战应用

```bash
# 创建公共上传目录
mkdir /data/upload
chmod 1777 /data/upload           # 所有人可写，但只能删自己的文件

# 测试
su - user1
touch /data/upload/file1.txt

su - user2
rm /data/upload/file1.txt         # ❌ Permission denied
```

## 四、特殊权限总结

| 权限 | 数字 | 作用对象 | 效果 | 显示 |
|------|------|---------|------|------|
| SUID | 4 | 可执行文件 | 以所有者身份执行 | s/S（所有者 x 位） |
| SGID | 2 | 可执行文件 | 以所属组身份执行 | s/S（所属组 x 位） |
| SGID | 2 | 目录 | 新文件继承目录组 | s/S（所属组 x 位） |
| Sticky | 1 | 目录 | 只能删自己的文件 | t/T（其他人 x 位） |

### 权限数字完整格式

```bash
# 完整格式：特殊权限 + 基本权限
chmod 4755 file                   # SUID + rwxr-xr-x
chmod 2755 dir                    # SGID + rwxr-xr-x
chmod 1777 dir                    # Sticky + rwxrwxrwx
chmod 6755 file                   # SUID + SGID + rwxr-xr-x
chmod 7777 dir                    # SUID + SGID + Sticky + rwxrwxrwx
```

## 五、实战案例

### 案例1：团队协作目录

```bash
# 需求：多人协作，文件自动属于项目组，不能删除别人的文件

# 1. 创建目录和组
mkdir /project/shared
groupadd project_team

# 2. 设置所属组
chgrp project_team /project/shared

# 3. 设置 SGID + Sticky Bit
chmod 3775 /project/shared        # 3 = 2(SGID) + 1(Sticky)
# drwxrwsr-t

# 4. 添加成员
gpasswd -a user1 project_team
gpasswd -a user2 project_team

# 效果：
# - 新文件自动属于 project_team 组（SGID）
# - 只能删除自己的文件（Sticky Bit）
```

### 案例2：公共上传目录

```bash
# 需求：所有人可以上传文件，但只能删除自己的

mkdir /data/public_upload
chmod 1777 /data/public_upload    # Sticky Bit
```

### 案例3：查找特殊权限文件

```bash
# 查找所有 SUID 文件
find / -perm -4000 -type f 2>/dev/null

# 查找所有 SGID 文件
find / -perm -2000 -type f 2>/dev/null

# 查找所有 Sticky Bit 目录
find / -perm -1000 -type d 2>/dev/null

# 查找所有特殊权限
find / -perm /7000 -ls 2>/dev/null
```

## 六、安全建议

### 1. 定期审计 SUID/SGID 文件

```bash
# 生成 SUID 文件列表
find / -perm -4000 -type f 2>/dev/null > /tmp/suid_files.txt

# 定期对比，发现异常
diff /tmp/suid_files.txt /tmp/suid_files_old.txt
```

### 2. 移除不必要的 SUID

```bash
# 如果不需要普通用户 ping
chmod u-s /usr/bin/ping
```

### 3. 保护关键目录

```bash
# /tmp 必须有 Sticky Bit
chmod 1777 /tmp

# 检查
ls -ld /tmp | grep -q 't$' || echo "Warning: /tmp missing sticky bit!"
```

## 七、特殊权限组合

```bash
# 常见组合
chmod 4755 file                   # SUID + rwxr-xr-x
chmod 2755 dir                    # SGID + rwxr-xr-x
chmod 1777 dir                    # Sticky + rwxrwxrwx
chmod 3775 dir                    # SGID + Sticky + rwxrwxr-x
chmod 6755 file                   # SUID + SGID + rwxr-xr-x
```

## 练习题

1. SUID 和 SGID 的主要区别是什么？
2. 为什么 /tmp 目录需要 Sticky Bit？
3. 如何创建一个团队协作目录，让新文件自动属于团队组？

<details>
<summary>答案</summary>

1. SUID 让执行者临时获得文件所有者权限，SGID 对文件让执行者获得所属组权限，对目录让新文件继承目录的组
2. /tmp 是公共目录，所有人可写，Sticky Bit 防止用户删除别人的文件
3. 创建目录，设置所属组，然后 `chmod 2775 directory` 设置 SGID

</details>
